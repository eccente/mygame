# 方块挪一挪 Web 版核心规则说明书 v1.3

## 1. 文档定位
本文件用于定义游戏的精确玩法规则、边界判定、事件优先级与道具行为。

后续开发中，只要涉及：
- 方块怎么移动
- 出口怎么判定
- 机关怎么结算
- 道具能对什么生效
- Three.js 场景如何映射逻辑状态

都以本文件为唯一基线。

## 2. 规则层与表现层约定

### 2.1 逻辑真相只存在于二维网格
本游戏虽然采用 `Three.js 2.5D` 渲染，但所有玩法逻辑都以 `二维网格状态` 为准。

这意味着：
- 碰撞以网格占格为准，不以模型边缘或视觉厚度为准
- 出口判定以逻辑边缘、出口跨度和完整离场条件为准，不以 3D 模型洞口尺寸为准
- 方块高度、阴影、倾斜角度都不改变占格关系
- 视觉回弹只是表现，不会改变最终逻辑坐标

### 2.2 不引入真实刚体物理
- 不使用重力、摩擦、弹性碰撞来决定玩法结果
- 不使用真实刚体堆叠作为核心机关
- 物理感仅用于表现层，例如轻微回弹、吸附缓动、清除时的位移动画

### 2.3 输入坐标映射
- Pointer 输入通过射线或平面映射转换为棋盘坐标
- 一旦转换为棋盘坐标，后续一切规则判断都按二维格子处理
- 相机角度变化不会改变规则结算

## 3. 术语定义
- `棋盘`：可放置方块的网格区域，不包含出口外侧空间。
- `格子`：棋盘上的最小单位。
- `锚点`：一个方块的左上角占格坐标。
- `目标方块`：需要从匹配出口完整离开棋盘并被清除的方块；当前版本默认所有可移动方块都是目标方块。
- `可移动方块`：存在于 `blocks` 列表中的可拖动方块，可能带有颜色、方向限制或特殊规则。
- `固定墙`：引擎保留概念，但主线与无限模式 v1 默认不使用的静态阻挡。
- `出口`：附着在棋盘边缘的收纳口，不占用棋盘内部格子。
- `机关格`：具有额外效果的特殊格子，如冰面、变色格、钥匙格、开关格等。
- `门`：可开闭的阻挡单元，如锁门、开关门、单向门。
- `本局`：从进入某一关到离开、通关、重置之前的单次尝试。
- `一次移动`：玩家按下、拖动、松手后产生的一次最终位移；或由机关衍生的一整段自动位移链。

## 4. 棋盘与坐标规则

### 4.1 坐标系
- 采用笛卡尔网格的离散坐标表示。
- `x` 从左到右递增，最左列为 `0`。
- `y` 从上到下递增，最上行为 `0`。
- 一个方块的逻辑位置由其 `锚点 (x, y)` 和 `shapeCells` 确定。
- `shapeCells` 表示该方块相对于锚点所占用的所有格子偏移。
- 棋盘采用 `固定 6 列 + 8~12 行` 的手机优先规格。
- 常用盘面为 `6x8~6x10`，`6x11` 用于高压主线，`6x12` 只用于极少数高难或无限模式高档位。

### 4.2 首发形状约束
首版固定主线支持以下可清除方块形状预设：
- `mono`：单格 `1` 格
- `domino`：两格长条
- `bar3`：三格长条
- `square-2`：`2x2` 方块
- `L-3`：三格小 L 形
- `L-4`：四格 L 形
- `T-4`：四格 T 形
- `cross-5`：十字型（`+字五格`）

约定：
- 第 `1` 章即可使用 `mono`、`domino`、`bar3`、`square-2` 组成高密度基础盘。
- `L-3`、`L-4` 在第 `2` 章尽早引入，先建立缺角借位读盘。
- `T-4` 在第 `3` 章引入，用来建立中心堵点与分流走廊。
- `cross-5` 在第 `4` 章引入，用来建立十字锚点与四向共享借位。
- `Z/S` 形明确排除，不进入主线与无限模式 v1。
- 无限模式 v1 仅在通过白名单的章节档位中渐进启用 `L / T / 十字型`，其中 `L` 最早，`T` 次之，`cross-5` 最晚且保持低权重。

### 4.2.1 形状族不是机制
- `mono`、`domino`、`bar3`、`square-2`、`L`、`T`、`十字型` 都是 `形状家族`，不是“特殊块类型”。
- 当前版本真正的特殊块类型只有 `方向限定目标块`。
- 因此关卡设计应先考虑“形状造成的空间问题”，再考虑“机制造成的规则问题”。

### 4.2.2 形状变体命名约定
- `mono` 使用 `default` 变体。
- `domino`、`bar3` 使用 `h / v` 表示横向或纵向。
- `square-2` 只有 `default` 变体。
- `L-3`、`L-4` 使用 `ur / dr / dl / ul` 表示四个朝向。
- `T-4` 使用 `up / right / down / left` 表示四个朝向。
- `cross-5` 使用 `default` 变体；该形状中心对称，不承载旋转语义。
- 规则层以 `shapeCells` 为最终真相；`shapePreset` 与 `shapeVariant` 只是便于编辑和维护的语义字段。

### 4.3 占格规则
方块占用的所有格子必须满足：
- 不越界
- 不与其他方块重叠
- 不与关闭状态的门重叠
- 不与固定墙重叠

## 5. 方块分类

### 5.1 目标方块
特征：
- 当前版本所有 `blocks` 都默认是目标方块
- 默认只使用 `颜色` 区分
- 颜色匹配且完整通过出口后被清除
- 可以触发大多数机关格
- 在 Three.js 场景中通常具有更明显的高光、边角圆润和主题材质

### 5.2 固定墙（引擎保留，不进入正式生成内容）
特征：
- 完全不可移动
- 不可被任何首发道具移除
- 只用于引擎保底能力或极端调试场景
- 主线与无限模式 v1 的正式关卡、生成器、校验器默认不使用

### 5.3 方向限定目标块
特征：
- 本质上仍然是目标方块，只是只能沿指定轴向移动
- 取值只有两种：`horizontal` 或 `vertical`
- 顶面必须带永久可见的 `箭头徽记`
- 被 `润滑油` 作用后，在本局中临时恢复为 `both`，并切换为“已润滑”状态的特殊徽记

### 5.4 主线特殊内容白名单 v1
按开发优先级分层如下：

- `P0 形状层`：`mono`、`domino`、`bar3`、`square-2`、`L-3`、`L-4`、`T-4`、`cross-5`
- `P1 稳定机制层`：方向限定块、锁门/钥匙格、单向门、简单开关门
- `P2 主线扩展层`：变色格
- `P3 高约束层`：冰面
- `P4 终章收束层`：不新增机制，只复用第 `6~11` 章的单机制高压题

说明：
- `P0` 不单独显示功能图标，默认只靠颜色识别。
- `P1` 可以进入无限模式 v1，但要受模板和权重限制。
- `P2/P3` 先只服务固定主线，不直接进入无限模式 v1。
- `P4` 只用于主线第 `12` 章，不作为无限模式模板来源。
- `Z/S`、旋转块、不可移除占位块、爆破/交换类机制不在 v1 范围内。

### 5.5 首次引入机制的教学原则
- 一关只引入一个新概念，不同时引入“新形状 + 新机关 + 新出口规则”三件事。
- 新机制第一次出现时，最好只和 `mono`、`domino` 或 `bar3` 组合。
- 新机制第二次出现再加入颜色顺序问题。
- 新机制第三次出现再开始和复杂形状或旧机制叠加。
- 如果某一机制需要额外图标说明，该图标必须在不看文字时也能读懂。

## 6. 操作与移动规则

### 6.1 输入模型
游戏使用 `连续滑动后吸附` 模式：
- 玩家按住一个可移动方块。
- 普通可移动块可在二维平面内自由拖动。
- 方向限定块只沿自身允许的方向移动。
- 松手时，方块吸附到最近合法格位。

### 6.2 移动约束
- 普通可移动块：默认可在棋盘内做二维拖动。
- 方向限定块：只允许沿指定轴向移动。
- 若玩家拖动方向与方向限定块规则不符，则系统按该块允许方向进行约束，不会穿透阻挡。

### 6.3 合法位移范围
系统需要实时计算方块当前可停留的合法位置集合：
- 合法位置必须满足不越界
- 不与其他方块、固定墙、关闭状态的门重叠
- 方向限定块仅在允许方向上变化坐标

渲染上允许方块在合法区域内连续平滑跟手；逻辑上只在松手时结算到格子坐标。

### 6.4 吸附规则
- 松手时，方块吸附到当前拖动位置最近的合法锚点。
- 若最近锚点与起始锚点相同，则视为 `无效移动`。
- 无效移动不改变盘面，只给出轻微回弹反馈。
- 回弹动画不会修改逻辑位置，只用于 Three.js 表现层。

### 6.5 移动不是自动滑行
基础规则下，玩家拖到哪里、松手后就停在哪里；不会自动继续滑到尽头。

只有以下情况会触发移动链的后续自动行为：
- 冰面
- 进入出口后清除

## 7. 出口规则

### 7.1 出口的定义
出口是贴附在棋盘边缘的 `实际开口`，不占用棋盘内部格子。

术语补充：
- `门组`：同一边上连续的一段同色出口
- `门槽`：门组覆盖的单个边界格
- 同色允许存在 `多个门组`
- 在当前正式形状池下，门组 `span` 统一控制在 `1~3`

每个出口包含：
- 所在边：`top / right / bottom / left`
- 起始位置
- 跨度 `span`（表示该开口在棋盘边缘上可容纳的连续格数）
- 可接受的 `颜色`

### 7.2 出口匹配条件
当一个目标方块完成移动后，只有同时满足以下条件，才会进入离场结算：
- 当前移动方向正对该出口所在边
- 方块在该边已经贴边
- 方块颜色与出口要求一致
- 方块沿该出口方向的 `投影跨度` 被完整包含在出口的 `[start, start + span)` 范围内

### 7.3 投影跨度与完整离场
- 左右出口看 `y` 方向投影跨度；上下出口看 `x` 方向投影跨度
- 该跨度按方块当前全部占格的最小值到最大值计算，不按“碰到门的那一格”计算
- 只有当该方块继续沿出口方向离场，并使全部占格都离开棋盘后，才算被清除
- 只要还有任意占格仍停留在棋盘内部，就不算出门成功

示例：
- `1x1` 方块需要 `1 格` 开口
- `1x2` 竖条从左右出口离开时，需要 `2 格` 高开口
- `L-4` 从左右出口离开时，按其当前 `y` 方向投影跨度判定，而不是按最先碰门的单格判定

### 7.4 错误出口处理
- 颜色不匹配时，不会清除
- 出口跨度不足时，不会清除
- 方块仍停留在最终吸附位置
- 给出轻微错误反馈，但不额外惩罚

### 7.5 当前版本的出口参与对象
- 当前版本所有可移动方块都参与出口判定
- 固定墙和门不参与出口判定
- 后续若引入“不可清除特殊块”，必须在关卡数据中显式声明，不能默认混入 `blocks`

## 8. 基础胜负规则

### 8.1 胜利条件
当关卡中所有可清除方块都被清除时，立即通关。

### 8.2 失败条件
首版不设置传统失败条件。

玩家可以：
- 一直尝试
- 随时重置本关
- 使用道具
- 随时退出并下次继续

### 8.3 重置本关
重置行为会恢复：
- 初始方块位置
- 所有门的初始开闭状态
- 所有临时机关状态
- 所有本局道具效果
- 所有 Three.js 动画中的临时表现状态

已消耗道具不返还。

## 9. 机关规则

### 9.1 锁门与钥匙格

#### 9.1.1 锁门
- 锁门本质上是初始关闭的可开启阻挡单元
- 锁门关闭时视为实心阻挡
- 锁门开启后，本局内保持开启

#### 9.1.2 钥匙格
- 钥匙格是棋盘内的触发格
- 当任意目标方块最终停在钥匙格上时，关联锁门立即开启
- 同一钥匙格只需触发一次

说明：
- 为降低理解成本，首版不区分“钥匙携带者”，任何可移动块都可触发钥匙格
- 这样更适合家庭向低门槛体验

### 9.2 开关门
- 开关门由 `开关格` 控制
- 当任意可移动块最终停在开关格上时，关联开关门执行 `翻转`
- 翻转规则：开 -> 关，关 -> 开
- 状态在本局持续保留，直到再次触发或重置本关

说明：
- 首版不做“站上去打开、离开就关闭”的压力门
- 使用翻转门更容易理解，也更容易保存与回放状态

### 9.3 单向门
- 单向门允许方块沿某一指定方向穿过
- 反向或侧向经过时视为阻挡
- 单向门的判定发生在 `路径合法性检查` 阶段，而不是落位后

### 9.4 冰面
- 当一个方块在一次移动结算后，其占格区域与冰面有重叠时，进入 `滑行状态`
- 滑行状态下，方块会沿当前方向自动继续前进
- 每前进 `1` 格都要重新判断是否仍可前进
- 若前方被阻挡，则停在阻挡前最后一个合法位置
- 若新的位置已不再覆盖任何冰面格，则滑行结束

设计约束：
- 固定主线中，冰面优先用于直线通道
- 无限模式 v1 仅在中后轮次低配额启用冰面

### 9.5 变色格
- 当目标方块最终停在变色格上时，立即把方块的 `颜色` 变为指定颜色
- 当前版本所有可移动方块都会被变色格改变
- 变色效果在本局持续，直到方块被清除或重置本关

设计约束：
- 首版主线中，变色格只以单一颜色切换为主，不做复杂链式染色
- 常规变色格默认使用 `1x1` 单格触发点；只有极少数教学或演出关才允许临时扩成多格
- 无限模式 v1 仅在中后轮次低配额启用变色格

### 9.6 终章收束规则
- 第 `12` 章不新增独立机制
- 单关只从 `方向限定 / 锁门钥匙格 / 单向门 / 开关门 / 变色格 / 冰面` 中选择 `1` 种作为主机制
- 终章关默认不叠加第二种高约束机制；若后续确需叠加，必须单独立项评审
- 终章仍严格遵守对应主机制的原始规则，不定义“终章专属机关”

## 10. 机关结算优先级
为避免实现与策划理解不一致，每次移动链中一个方块到达新位置后，按以下顺序结算：

1. `钥匙格 / 开关格`
2. `变色格`
3. `出口清除`
4. `冰面继续滑行`

### 10.1 这样设计的理由
- 先触发钥匙和开关，保证门状态在同一次移动链中立即生效
- 先变色，再判出口，保证“先染色后出门”成立
- 再判出口，保证大块离场与颜色匹配使用同一套稳定规则
- 最后再判断是否继续冰面滑行，使移动链逻辑稳定可预期

### 10.2 安全限制
- 一次移动链的机关跳转上限为 `32 次`
- 超过上限时，开发环境下记日志并强制停在当前合法位置
- 正式环境下不弹错，只静默保护

## 11. 道具规则

### 11.1 万能钥匙
- 价格：`120 金币`
- 目标：一个关闭中的锁门
- 效果：立即将其打开，并在本局内保持开启
- 不可作用于：固定墙、开关门、单向门

### 11.2 润滑油
- 价格：`140 金币`
- 目标：一个方向限定块
- 效果：把该块的移动轴向从 `horizontal/vertical` 改为 `both`
- 效果持续到本局结束或重置本关
- 不可叠加为额外速度或额外能力

### 11.3 金手指
- 价格：`180 金币`
- 目标：一个仍在棋盘内、尚未离场的 `可移动目标方块`
- 效果：立即将该方块从当前关卡中移除，视为“被道具清除”而不是正常出门离场
- 被移除的方块不触发出口、钥匙、开关、变色、冰面等常规移动链结算
- 不可作用于：门、机关格、固定墙、棋盘边框、已离场方块

### 11.4 道具白名单冻结
- 当前正式版本保留 `万能钥匙`、`润滑油`、`金手指`
- 不做 `清障锤`，因为正式关卡不再使用“不可清除障碍块”作为核心内容
- 不做 `传送手套`，因为它会绕开关卡主依赖链，不利于低冗余和唯主解目标
- 求解器 / 校验器 / 章节验收一律按 `不给道具` 前提执行，不把任何道具纳入可解性证明

## 12. Three.js 表现层约束

### 12.1 允许的表现型动画
- 轻微回弹
- 吸附缓动
- 清除时缩放与滑出
- 门开启动画
- 机关发光和提示脉冲

### 12.2 不允许影响规则的表现
- 模型旋转导致占格变化
- 视觉厚度导致额外碰撞
- 动画中途插入新的逻辑位置
- 基于帧率的规则结算差异

### 12.3 动画与逻辑的关系
- 逻辑先结算，动画后播放
- UI 和渲染层只能读取逻辑结果，不得在动画过程中篡改规则状态
- 需要“预演拖动”时，应使用临时视觉偏移，不修改逻辑锚点

## 13. 边界案例统一约定

### 13.1 方块已经贴边但没有形成完整离场
不触发清除。只要还有任意占格停留在棋盘内部，就视为仍在盘内。

### 13.2 一个大方块同时接触多个出口
- 必须存在至少一个出口同时满足颜色匹配、出口跨度完整容纳、当前移动方向一致
- 若多个匹配出口都成立，优先使用当前移动方向正对的那个出口

### 13.3 锁门刚被开启，是否影响本次后续移动
会影响。门状态在同一次移动链内实时更新。

### 13.4 冰面滑行到出口如何处理
- 滑行过程中每到达一个新的合法停点，都按 `钥匙/开关 -> 变色 -> 出口 -> 冰面` 的顺序立即结算
- 若该位置已满足完整离场，则立刻清除，不再继续滑行
- 若未离场且仍覆盖冰面，则继续沿原方向滑行

### 13.5 变色后能否立即进出口
可以。因为变色结算优先于出口判定。

### 13.6 道具引发的落位是否触发机关
会。道具不是特殊通道，只是改变方块或门状态，最终仍走常规规则链。

### 13.7 通关后是否还能继续操作
不能。进入结算态后，棋盘停止响应新的拖动和道具使用。

### 13.8 低帧率是否会改变结果
不会。低帧率只会影响表现流畅度，不会改变最终逻辑结算。

## 14. 规则复杂度控制
为了保证家用放松定位，首发版本遵守以下复杂度限制：
- 单关首次出现时只引入 1 个新机制
- 冰面与变色格不在同一主线章节同时首次出现；第 `12` 章不新增机制，只做终章收束
- 无限模式 v1 只使用较稳的规则子集
- 所有高级机关都必须能通过可视化样式一眼看懂
- 规则复杂度永远服从“清楚和稳定”，不为了 3D 视觉去额外引入物理不确定性
