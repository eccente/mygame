# 方块挪一挪 手机优先 UI/UX 重构方案 v1.1

## 1. 文档定位
本文件是在现有 `04-ui-ux.md` 基础上的进一步细化版，专门用于指导下一阶段的 UI/UX 改造。

本文件重点解决四类问题：
- 手机优先的页面结构怎么定
- 你提供的草图如何转成可开发的正式方案
- 页面之间的流转关系和弹层关系如何统一
- 游戏内“少文字、多图标、大棋盘”的体验如何具体落地

本文件不是视觉稿，不直接规定最终颜色、插画和细节动效；它是后续 UI 实现的“结构蓝图 + 交互规格 + 低保真线框说明”。

---

## 2. 本次方案依据
本方案基于以下约束与输入制定：
- 用户提供了首页 / 选关 / 设置 / 攻略 / 游戏页 / 道具购买页的草图
- 所有 UX 决策默认 `手机优先（mobile-first）`
- 用户体验目标是家人放松使用，避免学习成本和阅读压力
- 游戏玩法上不做步数和时间压迫
- 完美通关定义为：`不使用道具通关`
- 前提要求：每关后续都要保证存在“不用道具的解法”
- 主线模式和无限模式都采用：`先进入列表，再进入游戏`
- 所有道具都常驻显示；无库存时右下角显示 `0`
- 游戏页顶部信息布局固定为：
  - 左侧：设置 / 规则
  - 中间：模式 + 关卡信息
  - 右侧：金币
- 文字要尽量少，用图标和状态表达代替长句阅读

---

## 3. 总体设计目标

### 3.1 总目标
把当前原型改造成一个更接近“手机休闲挪车/挪块小游戏”的结构：
- 首页清楚
- 选关清楚
- 对局页面以棋盘为绝对主角
- 设置、规则、道具、购买都变成轻量、低打扰、可快速调用

### 3.2 体验关键词
- `手机优先`
- `大棋盘`
- `少文字`
- `强图标`
- `轻弹层`
- `低认知负担`
- `一眼知道下一步去哪`

### 3.3 记忆点
这套 UI 最应该让人记住的不是“装饰”，而是：
- 盘面很大，玩起来很直接
- 入口很少，不会迷路
- 图标比文字多，老人也容易看懂
- 模式、关卡、金币、道具这些信息总能快速找到

## 4. 设计原则

### 4.1 手机优先原则
所有页面先以 `竖屏手机 390 x 844` 左右的可用空间为第一设计目标。

优先级如下：
1. 保证棋盘可见面积最大化
2. 保证关键按钮可单手点击
3. 保证主要流程不需要长距离来回跳转
4. 保证文案在手机上不形成大段阅读负担
5. 桌面仅作为扩展布局，不反过来主导结构

### 4.2 大棋盘优先原则
进入游戏页后，视觉中心只能有一个：`棋盘`。

因此：
- 顶栏必须薄
- 规则和设置不占棋盘面积
- 道具栏不得抢占核心盘面高度
- 非必要说明不常驻大段文字

### 4.3 图标优先原则
能用图标表达的，不优先用整句文字。

建议：
- 设置：齿轮
- 规则：问号 / 书本
- 金币：金币图标
- 主线：旗帜 / 地图节点
- 无限：∞
- 继续：播放 / 回到上次进度
- 完美通关：星星 / 奖杯
- 未解锁：锁
- 当前进行：发光描边 / 小旗标
- 道具库存：右下角数量角标

### 4.4 弹层轻量原则
设置、攻略、购买都用轻量弹层，不切断主要流程。

规则：
- 优先弹层，而不是跳新页面
- 弹层不超过屏幕高度的 `78%`
- 弹层内容分组清楚，支持单手关闭
- 关闭方式统一：右上角 `X`

## 5. 页面架构重构

### 5.1 页面列表
重构后页面/层级建议保留为：
- `首页 / 模式入口页`
- `关卡列表页（主线 / 无限共用结构）`
- `游戏进行页`
- `设置弹层`
- `玩法攻略弹层`
- `道具购买弹层`
- `通关结算弹层`

### 5.2 流程主线
标准流程：
- 首页
- 选择模式
- 进入该模式的关卡列表
- 点击目标关卡
- 进入游戏页
- 通关后弹出结算
- 返回列表或进入下一关

### 5.3 继续游玩逻辑
首页保留一个非常明显的 `继续游玩` 入口。

逻辑：
1. 如果存在未完成中的关卡，直接回到该关卡
2. 如果无未完成局，则回到最近玩的模式的关卡列表，并高亮上次关卡
3. 如果没有任何历史进度，则从主线第 1 关开始

## 6. 首页设计方案

### 6.1 首页目标
首页不是信息页，而是分流页。

它只做三件事：
- 让玩家一眼看到自己有多少金币
- 让玩家快速进入：主线 / 无限 / 继续
- 提供设置入口

### 6.2 首页信息结构
顶部：
- 左：设置按钮（齿轮）
- 中：金币 + 数量
- 右：可保留轻量装饰或留白

中部：
- 背景氛围图：偏轻松，例如你草图里提到的 `蓝天白云海滩`
- 3 个主入口按钮纵向排列：
  - 主线模式
  - 无限模式
  - 继续游玩

底部：
- 当前版本不需要放太多文字
- 仅在需要时放一行极短说明，例如“看颜色，把目标送到边缘门槽”

### 6.3 首页线框（手机）
```text
┌──────────────────────┐
│ ⚙        金币 260        │
│                      │
│   背景氛围图 / 动态预览    │
│                      │
│   [ 主线模式 ]         │
│   关卡 x（最近进度）     │
│                      │
│   [ 无限模式 ]         │
│   关卡 x（最近进度）     │
│                      │
│   [ 继续游玩 ]         │
│   回到上次游玩的关卡     │
└──────────────────────┘
```

### 6.4 首页交互要求
- 点击 `主线模式`：进入主线关卡列表
- 点击 `无限模式`：进入无限模式关卡列表
- 点击 `继续游玩`：回到最近进度
- 点击 `设置`：弹出设置弹层

## 7. 关卡列表页设计方案

### 7.1 页面角色
这是你草图中间的核心区域，作用是承接模式入口，并把“选关”做得很清楚。

### 7.2 页面顶部信息
顶部建议保留一条轻量信息栏：
- 左：返回首页
- 中：当前模式名（主线 / 无限）
- 右：金币数量

次级信息：
- 当前章节页码 / 当前列表页码
- 当前高亮关卡提示

### 7.3 关卡卡片状态定义
每个关卡格子统一为卡片式小方块，支持以下状态：

1. `未解锁`
- 灰化
- 显示锁图标
- 不能点击

2. `已解锁未通关`
- 正常高亮
- 可点击
- 不显示额外徽记

3. `当前进行中的关卡`
- 外框高亮
- 顶部小旗标 / 小光圈
- 列表中默认滚动到该关附近

4. `已通关`
- 显示勾号
- 背景改为完成态颜色

5. `完美通关`
- 在已通关基础上增加 `星标`
- 完美含义固定为：`未使用道具`

### 7.4 主线与无限共用列表结构
用户确认主线和无限都先进入列表，因此 UI 采用同构：
- 都有列表
- 都可点击关卡进入
- 区别只是顶部模式标签、关卡组织方式、奖励提示文案不同

### 7.5 主线列表规则
- 按章节分页
- 每章显示 `1 / N` 页或横向翻章按钮
- 一屏建议 `6~9` 个关卡卡片
- 底部有 `进入游戏` 主按钮，进入当前选中的关卡

### 7.6 无限列表规则
无限模式列表不必做成长线章节，而是做成“单一卡片 + 当前轮次入口”结构：
- 动脑

卡片内显示：
- 最近进度
- 当前轮次
- 本轮累计奖励
- 是否有未完成的当前局

### 7.7 关卡列表线框（手机）
```text
┌──────────────────────┐
│ ←返回   主线模式   金币260 │
│ 第1章 · 海滩收纳         │
│                      │
│ [1★] [2✓] [3旗]       │
│ [4 ] [5✓] [6锁]       │
│                      │
│ ◀  第1页 / 共4页  ▶    │
│                      │
│      [ 进入游戏 ]      │
└──────────────────────┘
```

### 7.8 列表页交互要求
- 点击关卡卡片：只切换选中态，不立即进游戏
- 点击进入游戏：进入当前选中关卡
- 点击设置：弹出设置
- 点击规则：弹出攻略

## 8. 游戏进行页设计方案

### 8.1 页面角色
这是最关键的一页，必须严格做到：`盘面最大，信息最少，操作最短`。

### 8.2 顶部布局（按草图确认）
顶部固定信息区为三段：
- 左：`设置` + `规则`
- 中：`模式名 + 关卡名/关卡数`
- 右：`金币`

建议结构：
- 左侧只放图标按钮：
  - ⚙ 设置
  - ？规则
- 中间两行：
  - 第一行：模式名
  - 第二行：关卡信息 / 当前章节页
- 右侧：金币图标 + 数量

### 8.3 核心游戏区
游戏区只保留：
- 棋盘
- 出口
- 方块
- 极少量状态提示

不放：
- 大段规则说明
- 大面积静态文本
- 抢视线的装饰面板

### 8.4 底部道具栏
道具栏必须常驻显示所有道具。

规则：
- 每个道具都有固定槽位
- 图标右下角显示库存数量
- 没有库存时显示 `0`
- 点击行为：
  - 若库存 > 0：直接进入使用态
  - 若库存 = 0：弹出购买弹层

建议首版布局：
- 底部横向 `3 格`
- 图标优先，名称只在选中后或长按时出现
- 当前激活道具加高亮描边

### 8.5 游戏页线框（手机）
```text
┌──────────────────────┐
│ ⚙ ？   主线·1-3   金币260 │
│                      │
│     核心棋盘区域       │
│                      │
│                      │
│ [钥x1]   [油x0]   [指x0] │
└──────────────────────┘
```

### 8.6 游戏页状态提示方式
禁止常驻长句。

建议采用三层提示：
1. `静态顶栏信息`：模式、关卡、金币
2. `轻量小条提示`：例如“当前使用：润滑油”
3. `底部短 Toast`：例如“这里被挡住了”

### 8.7 游戏页信息最小化规范
- 规则说明默认不展开
- 引导内容仅在首次出现某机制时短暂显示
- 通常状态下，玩家只看到图标和棋盘
- 对于特殊方块，仅保留功能徽记，不再叠加装饰图案

## 9. 设置弹层方案

### 9.1 入口位置
- 首页右上或左上设置图标
- 游戏页左上设置图标

### 9.2 内容结构
设置弹层只保留高频、轻量选项：
- 音乐：开 / 关
- 音效：开 / 关
- 震动：开 / 关
- 返回首页

### 9.3 交互要求
- 右上角 `X` 关闭
- 不跳转新页
- 设置项采用开关组件
- 返回首页需要二次确认，避免误触

### 9.4 设置弹层线框
```text
┌──────── 设置 ────────┐
│ 音乐      开关       │
│ 音效      开关       │
│ 震动      开关       │
│                      │
│     [ 回到首页 ]      │
│                X      │
└──────────────────────┘
```

## 10. 玩法攻略弹层方案

### 10.1 入口位置
- 游戏页左上 `规则` 图标
- 关卡列表页可选同入口

### 10.2 结构目标
该弹层只做“快速读懂”，不做大篇教程。

建议分为 3 段：
- 基本规则
- 完美通关说明
- 道具说明

### 10.3 文案风格
- 每段最多 `2~3` 行
- 配图标
- 避免解释性长句

示例：
- 看颜色，把目标送到同色门槽
- 带箭头的方块受方向限制
- 不用道具通关即可拿到完美标记

### 10.4 攻略弹层线框
```text
┌──────── 玩法攻略 ──────┐
│ ① 基本规则             │
│ 看颜色，把目标送到边缘门槽 │
│                        │
│ ② 完美通关             │
│ 未使用道具通关          │
│                        │
│ ③ 道具说明             │
│ 卡住时再使用，非必需     │
│                  X      │
└──────────────────────┘
```

## 11. 道具购买弹层方案

### 11.1 触发方式
当玩家点击一个库存为 `0` 的道具槽位时，弹出购买弹层。

### 11.2 内容结构
购买弹层内容：
- 道具图标
- 道具名称
- 道具效果一句话说明
- 金币售价
- 购买按钮

### 11.3 交互要求
- 弹层不遮挡整个棋盘太久
- 支持点击蒙层关闭
- 购买完成后直接更新底部库存角标
- 若金币不足，购买按钮置灰或点击后短提示

### 11.4 购买弹层线框
```text
┌────── 购买道具 ──────┐
│     [ 道具图标 ]      │
│       润滑油          │
│ 让方向块本局恢复自由移动 │
│                        │
│     售价：140 金币     │
│    [ 购买 ]   [ 关闭 ]  │
└──────────────────────┘
```

## 12. 通关结算弹层方案

### 12.1 设计目标
结算弹窗不是展示页，而是一个`低阅读压力的结果确认层`。

它要在 1~2 秒内让玩家看懂三件事：
- 这关是否过了
- 这次是不是完美通关
- 下一步该点哪里

因此结算弹窗要遵循：
- 图标优先
- 信息分组少
- 文案短
- 主按钮非常明确

### 12.2 主线模式结算结构
主线模式采用`游戏页内居中弹窗`，不跳出到单独页面。

建议结构：
1. 顶部结果区
- 大图标：通关 / 完美通关
- 结果标题：`完成啦` / `完美通关`
- 极短副文案：如“本关已整理完成”

2. 奖励区
- 本关金币奖励
- 若为完美通关，可额外显示完美奖励或完美标记
- 若非完美通关，则显示“可重玩冲击完美”

3. 按钮区
- 主按钮：`下一关`
- 次按钮：`重玩本关`
- 文本按钮：`返回关卡列表`

### 12.3 主线模式状态分支
主线结算必须区分两种状态：

1. `普通通关`
- 主图标：勾号 / 完成徽记
- 标题：`完成啦`
- 次提示：`可重玩冲击完美`
- 奖励显示：基础金币

2. `完美通关`
- 主图标：星星 / 双星 / 勋章（保持与列表中的完美标记系统一致）
- 标题：`完美通关`
- 次提示：`未使用道具完成本关`
- 奖励显示：基础金币 + 完美奖励（如果后续数值方案中保留完美额外奖励）

### 12.4 主线模式结算线框（手机）
```text
┌──────── 通关结果 ───────┐
│        [ ★ / ✓ ]        │
│       完成啦 / 完美通关   │
│     未使用道具完成本关    │
│                         │
│   金币 +120   完美 +20    │
│                         │
│      [ 下一关 ]          │
│      [ 重玩本关 ]         │
│       返回关卡列表        │
└───────────────────────┘
```

### 12.5 结算弹窗视觉要求
- 弹窗宽度在手机上建议占屏宽 `78% ~ 88%`
- 中心对齐，背景加轻度遮罩
- 不使用大段说明文字
- 图标和奖励数字必须比解释文字更显眼
- 主按钮的视觉层级必须明显高于次按钮

### 12.6 无限模式结算
无限模式只有一个 `动脑` 档，因此结算不再承担档位区分功能，仍建议分两层：

1. `单局完成小结算`
- 采用顶部或底部轻提示条
- 展示：`+金币`、`连过 N 关`
- 不打断进入下一局

2. `退出总结弹窗`
- 玩家主动退出或一轮结束时展示
- 信息包括：
  - 本次连续完成关数
  - 本次累计金币
  - 历史最佳
- 按钮：
  - `继续这轮`
  - `返回列表`
  - `重新开始`

### 12.7 无限模式退出总结线框（手机）
```text
┌──────── 本轮总结 ───────┐
│        [ ∞ ]            │
│       连过 8 关         │
│     本轮获得 420 金币    │
│      历史最佳 12 关      │
│                         │
│     [ 继续这轮 ]         │
│     [ 重新开始 ]         │
│       返回列表           │
└───────────────────────┘
```

### 12.8 完美通关表现规范
完美通关采用图标强化：
- 星星 / 勋章
- 少量文字：`完美通关`
- 一句条件说明：`未使用道具`

避免长句说明。

### 12.9 交互细则
- 主线结算弹窗出现时，背景棋盘保留但不可误触
- 点击主按钮后立即进入下一关
- 点击重玩后回到本关初始状态
- 点击返回列表后回到当前模式的列表页，并高亮刚完成的关卡
- 若为普通通关，列表中只显示完成态；若为完美通关，列表中同步点亮完美标记

## 13. 图标系统建议

- 无限模式

不建议：
- 太细
- 太复杂

### 13.3 文案配合方式
- 首次出现：图标 + 短词
- 熟悉后：图标为主，文案可隐藏或缩短

## 14. 信息密度控制规范

### 14.1 单屏文字上限
手机单屏中，除弹层外，不建议同时出现超过 `3` 段明显文本信息。

### 14.2 游戏页文字上限
游戏页常驻文字只保留：
- 模式
- 关卡
- 金币
- 必要的极短状态提示

### 14.3 列表页文字上限
- 顶部标题
- 页码 / 章节
- 关卡卡片编号
- 极短按钮文案

其余尽量图标化。

### 15.1 手机（主方案）

- 游戏页：顶部薄信息栏 + 中间棋盘 + 底部常驻道具栏
- 弹层：居中但不全屏，保留关闭按钮

- 但核心逻辑仍以手机布局为源头
- 不允许为了桌面排版而让手机布局牺牲棋盘面积

## 18. 开发验收清单

### 18.1 首页验收
- 手机上三大入口是否一眼看懂
- 设置入口是否足够明显
- 金币是否清楚

### 18.2 选关页验收
- 是否一眼能分辨：已过、完美、当前、未解锁
- 关卡切换是否简单
- 主线 / 无限是否结构统一但不混淆

### 18.3 游戏页验收
- 棋盘是否明显比当前版本更大
- 顶部三段信息是否清楚
- 道具是否全部常驻可见
- 没库存是否明确显示 `0`
- 文字是否显著减少

### 18.4 弹层验收
- 是否能快速开关
- 是否不遮挡主流程太久
- 是否支持单手操作

### 18.5 手机优先验收
必须以真实手机视口作为首验环境：
- 390 x 844
- 393 x 852
- 412 x 915

桌面验收只作为补充。

## 19. 本方案结论
本次 UI/UX 设计方案的核心不是“把当前页面改好看一点”，而是完成以下结构性转变：
- 从“原型页面”转成“正式手机休闲游戏结构”
- 从“文字解释较多”转成“图标和状态主导”
- 从“菜单和游戏混在一个布局里”转成“首页 / 列表 / 游戏 / 弹层”的清晰分层
- 从“桌面适配思路”转成“手机优先，桌面跟随适配”

后续 UI 改造阶段，应严格以本方案为蓝图推进，而不是继续在当前原型页面上局部修补。
