# 方块挪一挪 Web 版开发版 PRD v1.3

## 1. 文档目的
本文件用于把“第二款小游戏”的方向方案升级为可执行的开发基线，并明确在引入 `Three.js 2.5D 渲染` 之后，产品边界、体验目标和技术方向如何统一。

本版重点解决以下问题：
- 明确产品目标与范围，避免开发中途反复改方向。
- 明确“3D 表现”和“规则玩法”之间的关系，避免把项目做成重物理游戏。
- 为后续规则实现、关卡制作、无限模式生成、性能优化和本地存档提供统一基线。

## 2. 已确认的固定决策
以下内容视为当前版本的硬约束：

- 游戏定位为 `家用放松型滑块解谜游戏`。
- 核心玩法为 `拖动方块，在有限空间内腾挪，把目标方块送入对应出口后清除`。
- 不做 `步数限制`。
- 不做 `时间限制`。
- 不做 `提示`。
- 不做 `撤销`。
- 保留 `免费重置本关`。
- 提供 `金币购买辅助道具` 作为卡关缓冲。
- 金币要给得 `相对大方`，不制造资源焦虑。
- 模式只保留 `主线模式` 与 `无限模式`。
- 不做 `家庭档案`，只保留单一玩家本地进度。
- 棋盘采用 `固定 6 列 + 8~12 行` 的手机优先规格，统一记作 `6xN`。
- 当前版本中，关卡内所有可移动方块都视为 `目标方块`，不再区分“阻挡块”和“目标块”。
- 首发形状白名单固定为 `mono`、`domino`、`bar3`、`square-2`、`L-3`、`L-4`、`T-4`、`cross-5`（十字型 / `+字五格`），明确不做 `Z/S` 型。
- 当前版本真正的“特殊方块”只保留 `方向限定目标块`；`L / T / 十字型` 只属于形状，不属于机制。
- 正式目标颜色池固定为 `6` 种：`red / blue / green / yellow / purple / orange`。
- 主线颜色节奏改为：`第 1 章固定 4 色`、`第 2 章固定 5 色`、`第 3 章起固定 6 色全部上`。
- 关卡目标占格率统一控制在 `65%~80%`，章节内部再分教学 / 常规 / 高压带。
- 主线机制按 `方向限定 -> 锁门/钥匙格 -> 单向门 -> 开关门 -> 变色格 -> 冰面` 递进引入；第 `12` 章不新增机制，改为终章收束章。
- 方块出门必须满足 `颜色匹配 + 出口跨度完整容纳 + 整体离开棋盘`，不能只凭单格接触就清除。
- 操作方式采用 `连续滑动后吸附`，不是点一下自动走到底，也不是逐格点击移动。
- 锁门打开后为 `本局常驻开启`，直到重置本关。
- 方向限制被道具解除后为 `本局解除`，直到重置本关。
- 暂不考虑 `关卡编辑器`。
- 渲染核心采用 `Three.js`，视觉目标为 `2.5D / 轻 3D`。
- 游戏逻辑采用 `JavaScript 自定义规则引擎`，不是重刚体物理模拟。
- 不以“真实物理”作为玩法核心，只在表现层使用轻量回弹、缓动和碰撞感。
- 性能目标写法为：`在主流中端移动设备与桌面浏览器上，主要游玩场景保持接近 60 FPS，稳定落在 55~60 FPS 区间`。
- 浏览器兼容目标写法为：`兼容 Chrome、Safari、Edge、Firefox 的主流 WebGL 环境`。
- 对不支持 WebGL 的环境，首版只做 `不进入游戏并给出兼容提示`，不额外实现完整 2D 回退版本。

## 3. 产品定义

### 3.1 一句话定义
`一款通过拖动彩色方块完整离开对应出口来清空棋盘的轻松解谜游戏，拥有大量固定主线关卡，并通过无限模式提供长期可玩内容。`

### 3.2 产品定位
- 类型：单机、低压、轻解谜、解压整理感小游戏
- 平台：手机浏览器优先的 Web 版，桌面浏览器兼容
- 玩法内核：规则驱动的网格解谜
- 视觉包装：Three.js 2.5D 立体玩具盘面
- 使用场景：家人日常放松、碎片时间消遣、随手开一关

### 3.3 产品气质
- 温和，不催促
- 清爽，不吵闹
- 规则简单，但可以慢慢变深
- 看得懂、拖得顺、卡住也有出口
- 有立体感，但不依赖真实物理复杂性

## 4. 渲染与技术定位

### 4.1 为什么使用 Three.js
Three.js 的作用不是把本游戏改造成“真实 3D 物理游戏”，而是为这款本来就适合家用放松的产品提供更舒服的立体视觉表现。

选择 Three.js 的目标是：
- 让方块、出口、墙体和机关具有清晰的空间层次
- 让拖动、吸附、清除和机关触发拥有更好的视觉反馈
- 让整个游戏更像“桌面玩具盘”而不是平面 demo
- 仍然保持规则逻辑完全可控、可解、可调试

### 4.2 Three.js 的职责
- 负责棋盘、方块、出口、机关、灯光、阴影和动画表现
- 负责 2.5D 相机视角和视觉空间感
- 负责把逻辑状态映射为立体场景对象

### 4.3 Three.js 不负责的内容
- 不负责核心解谜规则
- 不负责碰撞判定逻辑
- 不负责关卡可解性判断
- 不负责无限模式生成
- 不负责重物理模拟

### 4.4 自定义规则引擎的职责
- 负责网格坐标和占格计算
- 负责移动合法性
- 负责出口判定
- 负责机关优先级和道具效果
- 负责胜利判定
- 负责为无限模式求解器与生成器提供统一逻辑

### 4.5 性能目标表达
为了避免不现实的绝对承诺，本项目的性能目标采用如下表述：
- 在主流中端移动设备与桌面浏览器上，主要游玩场景保持 `55~60 FPS`
- 主线和无限模式的正常关卡推进过程中，视觉体验应接近 `60 FPS`
- 在低端设备或 Safari 某些机型上，允许通过关闭阴影、降低像素比、减少粒子等方式维持稳定体验

### 4.6 浏览器兼容目标
- 支持 `Chrome`、`Safari`、`Edge`、`Firefox` 的主流 WebGL 环境
- 首版以 `WebGLRenderer` 为主要渲染路径
- 对 WebGL 上下文丢失要有恢复或重新进入能力
- 对完全不支持 WebGL 的环境，显示兼容提示页

## 5. 目标用户与使用场景

### 5.1 目标用户
- 喜欢轻度解谜，但不喜欢高压失败的用户
- 喜欢“整理、收纳、清盘”式满足感的用户
- 平时会使用手机浏览器玩轻量小游戏的家庭成员
- 对复杂操作和复杂系统不耐受的轻度玩家
- 喜欢稍有质感、但不想被重 3D 操作拖累的玩家

### 5.2 典型使用场景
- 饭后随手玩 2~3 关
- 晚上坐着慢慢琢磨一章
- 打完主线后进入无限模式继续玩
- 卡住时用金币买一个道具，继续推进，不被硬卡
- 在手机上短时打开，也能获得较好的立体视觉反馈

## 6. 产品目标

### 6.1 体验目标
- 玩家在 `10 秒内` 明白“颜色对应出口、所有块都要送出、箭头只表示特殊移动限制”的核心规则。
- 玩家在 `30 秒内` 完成第一关。
- 玩家在前 `20 关` 内稳定建立“这游戏不着急，慢慢玩就行”的印象。
- 玩家在任何时刻都可以通过 `重置本关` 或 `使用道具` 找到继续游玩的出口。
- 玩家从第一次进入开始，就能感受到“像在挪一个立体桌面玩具”的视觉质感。

### 6.2 内容目标
- 主线首个完整版本提供 `360 关` 固定关卡。
- 无限模式可以稳定持续生成可解关卡，成为主线打完后的长期内容来源。
- 主线和无限模式都围绕同一套规则运行，避免形成两套割裂产品。

### 6.3 技术目标
- 规则系统必须可模块化实现，方便后续继续加关卡和加机制。
- 关卡数据必须结构化，避免把关卡硬编码进逻辑里。
- 无限模式必须具备 `可复现 seed` 和 `可解校验` 机制。
- 渲染层必须与规则层分离，避免 Three.js 场景对象直接承担规则真相。
- 需要为性能优化预留明确策略：对象复用、共享材质、限制光源、限制粒子、按设备分级。

## 7. 明确不做的内容
- 不做体力系统
- 不做签到系统
- 不做广告驱动设计
- 不做充值与付费商店
- 不做排行榜导向竞争
- 不做提示按钮
- 不做撤销按钮
- 不做失败后强制惩罚
- 不做多人档案
- 不做联网与云存档
- 不做 UGC 关卡编辑器
- 不做真实重力、摩擦、刚体堆叠等重物理玩法
- 不做依赖后处理特效的重 3D 画面方案

## 8. 核心玩法概述

### 8.1 核心目标
将棋盘中的所有可移动方块送入对应颜色的出口，直到清空棋盘。

补充约束：
- 棋盘采用 `固定 6 列 + 8~12 行` 的手机优先规格，主线常用 `6x8~6x10`，极少数高压关使用 `6x11~6x12`。
- 当前版本中，关卡内所有可移动方块都属于清盘目标。
- 固定墙、门和机关不计入清盘目标。

### 8.2 基础操作
- 玩家按住一个可移动方块并拖动。
- 普通方块在合法区域内连续跟随手指移动；方向限定块只沿允许方向移动。
- 松手时，方块吸附到最近合法格位。
- 若最终位置满足匹配出口的完整通行条件，并在结算后整体离开棋盘，则方块被清除。
- 整个过程在视觉上表现为立体方块滑行，但逻辑上仍是二维网格结算。

### 8.3 核心乐趣来源
- 观察：找出谁在挡路，哪个出口先开
- 腾挪：给关键方块腾出空间
- 清盘：一个个送出目标方块，盘面越来越干净
- 兜底：卡住时使用道具，而不是被惩罚
- 观感：拖动与清除时具有玩具盘面的立体满足感

## 9. 模式设计

### 9.1 主线模式
主线模式负责提供稳定、节奏良好、机制逐步引入的固定内容。

主线规则：
- 共 `12 章`
- 每章 `30 关`
- 总计 `360 关`
- 每章前 `20 关` 为主推进内容
- 每章后 `10 关` 为附加内容
- 完成每章前 `20 关` 可解锁下一章

这样设计的目的：
- 保证关卡“很多”
- 避免因为个别关卡住就完全无法推进
- 给愿意深玩的人更多附加内容
- 让 Three.js 主题外观可以随章节逐步变化，但不破坏主规则学习

### 9.2 无限模式
无限模式负责提供长期内容续航，但从现在开始只保留一个外显档位：`动脑`。

无限模式原则：
- 没有终点
- 没有时间压力
- 没有失败惩罚
- 当前关永远可以重置
- 玩家可以随时中断并下次继续
- 无限模式优先保证 `稳定生成 + 稳定帧率 + 低重复`
- 难度整体对标**计划中的主线第 `6` 章后 `10` 关**，不是当前仓库里的半成品关卡

无限模式不再提供 `轻松 / 普通 / 动脑` 三档，而是长期稳定维持在第 `6` 章 brutal 带附近。

## 10. 内容体量规划

### 10.1 主线章节规划
- 第 1 章：收纳入门
- 第 2 章：双色顺序
- 第 3 章：长条与方阵
- 第 4 章：L 型腾挪
- 第 5 章：T 型拼盘
- 第 6 章：方向训练
- 第 7 章：锁链车间
- 第 8 章：单向站台
- 第 9 章：开关仓
- 第 10 章：染色工坊
- 第 11 章：冰面实验室
- 第 12 章：终章拼盘

### 10.2 主线白名单与排除项
首发主线内容按三层理解：
- `基础形状层`：`mono`、`domino`、`bar3`、`square-2`
- `复杂形状层`：`L-3`、`L-4`、`T-4`、`cross-5`
- `特殊规则层`：方向限定、锁门/钥匙格、单向门、开关门、变色格、冰面

明确排除：
- `Z/S` 异形块
- 可旋转方块
- 需要单独清障的占位块
- 依赖真实物理推动/挤压的机关

### 10.3 无限模式支持范围
为保证生成质量，`无限模式 v1` 采用“高密度基础盘 + 低配额章节机关”的支持范围：
- 支持：普通目标块、多格目标块、`L / T / 十字型` 异形块、方向限定块
- 机关：锁门/钥匙格、单向门、开关门、变色格、冰面，按回合阈值渐进解锁
- 出口：允许 `同色可多门`
- 约束：单局只注入少量章节机关，坏题允许由金币道具兜底
- 明确不进入：`Z/S`、旋转块、不可移除占位块

### 10.4 主线与无限模式的分工
- 主线负责 `教学、引入新规则、控制组合节奏`
- 无限模式负责 `长期内容、稳定可解、低重复`
- 凡是首次阅读成本高、状态链长、对生成器约束重的机制，先在主线固定关中验证
- 只有通过固定关验证且生成约束清晰的机制，才进入无限模式池

## 11. 金币与道具总策略

### 11.1 总原则
- 只保留一种货币：`金币`
- 金币只通过游玩获得
- 金币的主要用途是购买辅助道具
- 金币要给得大方，让玩家敢用道具

### 11.2 奖励节奏
主线模式：
- 第 1~4 章首次通关：`80 金币 / 关`
- 第 5~8 章首次通关：`100 金币 / 关`
- 第 9~12 章首次通关：`120 金币 / 关`
- 已通关关卡重复通关：`30 金币 / 关`
- 完成每章前 `20 关`：额外奖励 `400 金币`
- 完成整章 `30 关`：额外奖励 `600 金币`

无限模式：
- 动脑档：`80 金币 / 关`
- 连续完成 `5 关`：额外 `250 金币`
- 连续完成 `10 关`：额外 `600 金币`

### 11.3 首发道具白名单
- `万能钥匙`：打开一个锁门，`120 金币`
- `润滑油`：让一个方向限定块在本局恢复自由移动，`140 金币`
- `金手指`：直接移除一个可移动目标方块，`180 金币`

设计意图：
- 2~3 关主线即可购买一个基础道具
- 卡关时有明确缓冲手段
- 不需要“攒很久才舍得用”

当前冻结：
- 首发保留 `3` 个道具：`万能钥匙 / 润滑油 / 金手指`
- 不再做 `清障锤`，因为正式关卡不再使用独立障碍块
- 不再做 `传送手套`，因为它会显著破坏低冗余解法控制，且当前版本已取消传送主线规划
- `金手指` 只对盘内 `可移动目标方块` 生效，不作用于门、机关格、固定墙等结构对象

## 12. 体验原则

### 12.1 看得懂
- 目标方块和出口默认只用 `颜色` 对应
- 只有带特殊规则的对象才额外使用 `箭头/锁/开关` 等功能徽记
- 没有特殊规则的普通方块尽量不加无意义图案，避免误导
- 新机制一次只教一个

### 12.2 拖得顺
- 拖动反馈必须即时
- 合法位置吸附必须清楚
- 被挡住时要有明确回弹提示
- 渲染动画不能破坏逻辑响应速度

### 12.3 不着急
- 没有时间条
- 没有倒计时
- 没有“超步数失败”
- 没有连续失败惩罚

### 12.4 关卡多
- 主线先给足固定内容
- 无限模式保证“打完主线还有得玩”

### 12.5 卡住也能继续
- 免费重置本关
- 用金币买道具
- 不让玩家被一个错误操作长期卡住

### 12.6 立体但不复杂
- 视觉可以更精致，但操作和规则不增加额外负担
- 立体效果服务于识别、手感和满足感，不服务于炫技

### 12.7 性能稳定优先
- 画面细节必须服从流畅度
- 若设备性能不足，应优先关闭阴影和复杂动画，而不是牺牲基本操作响应

## 13. 版本规划

### 13.1 原型版
目标：验证玩法和 Three.js 2.5D 手感是否成立。

包含：
- 一个可操作棋盘

### 13.2 MVP
目标：形成可长期游玩的首个完整版本。

包含：

- 3 个道具（`万能钥匙 / 润滑油 / 金手指`）
- 商店
- 本地存档
- 无限模式 `动脑` 单档
- 设备分级渲染策略

目标：达到当前方案定义的完整形态。

包含：
- 主线 `360 关`
- 无限模式 `动脑` 单档
- 全套首发机制范围
- 备份接入
- 视觉、音效、动画完善

## 14. 首版验收基线
达到以下条件，才视为“方案落地成功”：

- 玩家第一次进入时能在无教程长文情况下完成前 3 关
- 主线前 30 关不存在明显难度断层
- 道具可以真实缓解卡关，而不是形式存在
- 无限模式能稳定生成可解关卡，不频繁重复
- 退出后再次打开，能够恢复最近一次游戏状态
- 首页到游戏页的路径清晰，能快速继续上次进度
- 在主流中端移动设备和桌面浏览器上，主玩法过程基本保持在 `55~60 FPS`
- 在 Chrome、Safari、Edge、Firefox 的主流 WebGL 环境中能正常进入和游玩
