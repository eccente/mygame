# 方块挪一挪 Web 版页面结构与交互说明 v1.2

## 1. 文档定位
本文件定义游戏的：
- 页面信息架构
- 页面之间的流程关系
- HUD 与按钮布局
- Three.js 2.5D 画面表现规范
- 动效、音效、引导与可访问性规范

目标是让后续前端开发可以直接依据本文件拆页面和交互，而不是边做边猜。

## 2. 视觉总方向

### 2.1 视觉定位
本游戏采用 `Three.js 2.5D 立体玩具盘` 风格：
- 逻辑是二维网格
- 视觉是轻立体空间
- 相机有轻微俯视角
- 方块、出口、墙体有明确厚度
- 阴影和高光强化“桌面玩具感”

### 2.2 设计原则
- 立体感服务于识别，不服务于炫技
- 盘面信息优先于装饰
- 相机角度必须稳定，避免让玩家头晕或误判位置
- 特效必须服从流畅度

### 2.3 推荐视觉风格
- 主题：`玩具工坊 + 收纳感`
- 材质：圆角塑料块、轻木质出口框、哑光墙体
- 灯光：温暖、柔和、不过度真实
- 整体印象：像在整理一盘桌面拼块玩具

## 3. 入口策略
结合当前仓库结构，建议第二款小游戏采用 `独立页面 + 首页入口卡片` 的形式。

推荐方式：
- 在 `index.html` 首页增加“方块挪一挪”入口卡片
- 新增独立页面 `shift.html`
- 该页面独立加载自己的脚本和样式，不与现有 `app.js` 强耦合

这样做的优点：
- 与现有 `game.html` 和 `health.html` 的组织方式一致
- 第二款游戏可以独立演进
- 规则和 UI 不需要硬塞进现有 shell 的视图切换体系

## 4. 页面信息架构

### 4.1 页面列表
- 首页入口卡片
- 游戏主菜单页
- 主线章节页
- 主线关卡页
- 游戏进行页
- 通关结算页
- 无限模式准备页
- 商店页
- 设置页
- 兼容提示页

### 4.2 页面流转总览
- `index.html` -> `shift.html`
- `shift.html` 首先做 WebGL 能力检查
- 若兼容，则进入 `主菜单`
- 若不兼容，则进入 `兼容提示页`
- 主菜单可进入：
  - 继续游戏
  - 主线模式
  - 无限模式
  - 商店
  - 设置
- 主线模式 -> 章节页 -> 关卡页 -> 游戏页 -> 结算页
- 无限模式 -> 准备页 -> 游戏页 -> 轻量结算提示 -> 下一局 / 退出总结

## 5. 首页入口卡片规范

### 5.1 卡片内容
首页卡片建议包含：
- 游戏名：`方块挪一挪`
- 一句话描述：`拖动方块，送进对应出口`
- 主按钮：`继续` 或 `开始`
- 次按钮：`进入游戏`
- 辅助信息：最近进度，如 `主线 3-12` 或 `无限 普通 8 连`

### 5.2 卡片视觉重点
- 用一张清楚表现“立体方块 + 出口”的缩略图
- 避免放过多说明文字
- 一眼看出这是“第二款游戏”而不是工具模块

## 6. 主菜单页规范

### 6.1 页面目标
主菜单页承担两个任务：
- 让玩家最快继续上次游玩
- 让玩家明白游戏只有几个简单入口，不复杂

### 6.2 页面布局
推荐布局：
- 顶部：返回首页按钮、标题、金币显示
- 中部：大按钮区
- 底部：最近进度、版本号、小型设置入口
- 背景：轻量 Three.js 静态预览场景或低成本动态背景

### 6.3 主按钮优先级
按钮顺序建议：
1. `继续游戏`
2. `主线模式`
3. `无限模式`
4. `商店`
5. `设置`

### 6.4 继续游戏逻辑
优先级：
1. 若存在未完成的当前局，则继续该局
2. 否则回到最近一次进入的模式入口
3. 若无任何进度，则进入主线第 1 关

## 7. 主线章节页规范

### 7.1 页面目标
展示 12 章结构，让玩家清晰知道自己玩到哪里。

### 7.2 每个章节卡片显示内容
- 章节编号与名称
- 解锁状态
- 已完成关卡数，如 `18 / 30`
- 简短主题说明
- 当前章的代表视觉元素

### 7.3 解锁表现
- 已解锁：正常彩色展示
- 未解锁：灰化但仍显示名称，避免“内容消失感”

## 8. 主线关卡页规范

### 8.1 页面目标
展示当前章节 30 关的结构，同时支持快速回到最近进度。

### 8.2 关卡格展示内容
- 关卡号
- 已通关状态
- 当前推荐进入关高亮
- 附加关与主推进关做轻微区分

### 8.3 推荐视觉分区
- `1~20` 主推进关作为主分区
- `21~30` 附加关作为次分区

## 9. 游戏进行页规范

### 9.1 页面目标
游戏页必须把注意力集中在棋盘上，HUD 信息尽可能少而清楚。

### 9.2 页面布局
推荐结构：
- 顶部左：返回按钮
- 顶部中：关卡标题或模式名
- 顶部右：金币、商店按钮、重置按钮
- 中央：Three.js 棋盘视图
- 底部：3 格常驻道具栏

### 9.3 HUD 文案
主线模式：
- 中央标题：`第 3 章 · 第 12 关`

无限模式：
- 中央标题：`无限模式 · 普通`
- 副信息：`当前连过 7 关`

### 9.4 棋盘显示原则
- 棋盘区域是视觉中心，优先保证足够大
- 出口必须明显显示在边缘
- 方块与出口必须可通过 `颜色` 快速对应；特殊规则再通过功能徽记补充
- 机关格必须有一眼看懂的图标
- Three.js 相机角度固定，不允许自由旋转

### 9.5 互动反馈
- 点击方块：高亮对应出口
- 点击出口：高亮对应目标方块
- 拖动开始：方块有轻微抬起感
- 拖动中：合法范围内连续跟手
- 松手吸附：明确落位
- 被阻挡：轻微回弹
- 清除出门：有收纳感动画和音效

## 10. Three.js 场景表现规范

### 10.1 相机方案
建议使用 `OrthographicCamera` 或轻透视的固定俯视相机。

推荐原则：
- 不允许玩家旋转相机
- 不允许因为相机动画改变关卡阅读性
- 视角固定为“偏俯视、略带深度”的稳定方案

推荐首选：
- 以 `OrthographicCamera` 为主
- 用轻微倾斜和层次表现 2.5D 立体感

### 10.2 灯光方案
建议采用低成本稳定灯光：
- 1 个主方向光
- 1 个环境光
- 必要时加 1 个半球光或补光

约束：
- 不使用复杂多光源动态阴影叠加
- 不使用重后处理辉光作为主视觉依赖

### 10.3 材质方案
建议使用共享材质和统一风格：
- 普通可移动方块：圆角塑料 / 漆面玩具材质，以纯色顶面为主
- 特殊规则方块：在普通方块基底上叠加箭头等功能徽记，不额外换成第二套块体语言
- 墙体：低细节稳定材质
- 出口：整体染色的收纳槽 + 高可见度边框，不叠加独立图案贴片

### 10.4 场景动效边界
允许：
- 方块轻微浮动阴影
- 吸附缓动
- 清除粒子
- 门开启动画
- 机关发光提示

不建议：
- 大面积粒子风暴
- 频繁镜头推拉
- 长时间屏幕震动
- 复杂后处理链

## 11. 通关结算页规范

### 11.1 主线模式结算
通关后弹出轻量结算面板：
- 标题：`完成啦`
- 本关获得金币
- 当前总金币
- 主按钮：`下一关`
- 次按钮：`重玩本关`
- 文本按钮：`返回关卡页`

### 11.2 无限模式结算
无限模式不建议每关都弹全屏结算。

推荐方式：
- 每关通关后显示一个 `顶部或底部轻提示条`
- 展示：`+50 金币 · 连过 4 关`
- 延迟 `0.8~1.2 秒` 后自动进入下一局

### 11.3 无限模式退出总结
玩家主动退出时，再展示完整总结：
- 本次连续完成关数
- 本次累计金币
- 历史最佳连续记录
- 按钮：`继续这轮` / `返回主菜单` / `重新开始`

## 12. 无限模式准备页规范

### 12.1 页面目标
让玩家以最少操作进入无限模式。

### 12.2 页面内容
- 三个难度档卡片：轻松 / 普通 / 动脑
- 若存在未结束的无限模式存档，则额外显示：
  - `继续上次无限模式`
- 说明文案只保留一行：
  - `没有时间限制，想玩多久就玩多久`

## 13. 商店页规范

### 13.1 页面目标
商店必须极简，只承担“买道具”这一件事。

### 13.2 展示内容
每个道具项展示：
- 图标
- 名称
- 一句话用途
- 当前库存
- 价格
- 购买按钮
- 小型 Three.js 或静态图标式道具预览都可，但不得影响商店响应速度

### 13.3 推荐道具排序
1. 万能钥匙
2. 润滑油
3. 金手指

### 13.4 道具说明文案
- `万能钥匙`：打开一扇锁门
- `润滑油`：让方向块本局自由移动
- `金手指`：直接移除一个方块

## 14. 设置页规范

### 14.1 保留项
- 背景音乐
- 音效
- 震动反馈
- 色弱辅助
- 减少动效
- 画面质量：`标准 / 省电`

### 14.2 画面质量说明
- `标准`：阴影与常规动画正常开启
- `省电`：关闭阴影、降低像素比、减少粒子和发光

### 14.3 不建议加入的内容
- 复杂画质选项
- 多套输入模式切换
- 复杂账号相关设置

## 15. 新手引导规范

### 15.1 引导原则
- 用手势演示代替长文字
- 每次只教一个东西
- 只在首次遇到新机制时触发

### 15.2 首次开局引导
第 1 关只展示：
- 拖动方块
- 对应出口
- 清除成功

第 2 关展示：
- 先给其他目标块腾空间

第 3 关展示：
- 不同颜色进不同出口

第 4 关展示：
- 箭头方块只按箭头方向移动
- 润滑油会临时解除方向限制

### 15.3 机制引导形式
使用：
- 短暂遮罩
- 手指动画
- 1 句短说明

不使用：
- 多页说明弹窗
- 大段规则文字

## 16. 可访问性与家庭友好规范

### 16.1 视觉识别
- 默认目标样式采用 `颜色` 区分
- 特殊规则统一通过功能徽记表达，例如 `箭头`、`锁`、`开关`
- 如开启色弱辅助，可额外显示文字标签或高对比边框，但不改变默认极简方案

### 16.2 触控尺寸
- 重要按钮触控区域不小于 `44px`
- 道具栏按钮不小于 `52px`

### 16.3 文字与布局
- 文案短句化
- 关键按钮固定位置
- 减少层级跳转

### 16.4 动效控制
- 默认有轻动效
- 开启“减少动效”后，关闭夸张缩放与长时间过渡
- 开启“省电”后，Three.js 场景应同步降级

## 17. 音效与动效规范

### 17.1 动效节奏
- 拖动跟手：即时
- 吸附：`100~150ms`
- 被挡回弹：`80~120ms`
- 清除吸收：`160~220ms`

### 17.2 音效类型
- 滑动：柔和短音
- 阻挡：轻微咔哒声
- 清除：带收纳感的满足音
- 通关：轻庆祝，不夸张

## 18. 兼容提示页规范

### 18.1 触发条件
- WebGL 不可用
- Three.js 渲染器初始化失败
- 关键图形能力缺失且无法通过省电模式正常运行

### 18.2 页面内容
- 标题：`当前浏览器暂不支持该游戏画面`
- 简短说明：`请尝试使用新版 Chrome、Safari、Edge 或 Firefox`
- 按钮：`返回首页`

### 18.3 首版策略
首版不实现完整 2D 回退版，只提供清晰兼容提示。

## 19. 页面实现建议
为兼顾可维护性与当前仓库结构，推荐：
- 外层页面与按钮使用 DOM
- 棋盘区域使用 Three.js 渲染
- 浮层、商店、设置页使用 DOM 弹层
- HUD 与 Three.js 场景之间通过状态层通信，而不是直接互相调用
