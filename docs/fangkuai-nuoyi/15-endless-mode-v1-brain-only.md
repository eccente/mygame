# 方块挪一挪无限模式 v1（动脑单档）方案

## 1. 文档定位
本文件用于冻结无限模式的最终产品方向，回答三件事：
- 无限模式还要不要保留多档位。
- 无限模式 `v1` 的内容边界是什么。
- 它与主线第 `6` 章、生成器 `v3`、校验器三层接口如何接线。

本文件结论优先于旧的“轻松 / 普通 / 动脑三档”口径。
从现在开始，外显给玩家的无限模式只保留：
- `动脑`

相关文档：
- `docs/fangkuai-nuoyi/01-prd.md`
- `docs/fangkuai-nuoyi/03-level-and-endless.md`
- `docs/fangkuai-nuoyi/08-mobile-first-ui-ux-redesign.md`

## 2. 最终冻结结论

### 2.1 只保留一个无限档位
无限模式取消：
- `轻松`
- `普通`

只保留：
- `动脑`

原因：
- 生成器候选池不再被三个档位拆散，质量更容易做高。
- UI 更简单，手机端入口更直接。
- 长期游玩时，玩家记忆的不是“我今天玩哪一档”，而是“我当前连过到第几关”。
- 当前项目真正需要的是“稳定、可持续、足够烧脑”的无限模式，而不是表面上档位很多。

### 2.2 难度基准
无限模式 `v1` 的外显难度，不再使用“从低到高三档并列”逻辑，而改为：
- **整体对标计划中的主线第 `6` 章后 `10` 关**
- 也就是对标：`第 6 章 21~30 关` 的正式成品目标
- **明确不是对标当前仓库里现有的第 6 章半成品关卡**

更准确地说：
- 它不是“越来越简单的无限模式”
- 也不是“无限抬高到终章级别的爬塔模式”
- 而是长期稳定维持在 `第 6 章 brutal 带` 附近，允许少量波动

### 2.3 内容基准
无限模式 `v1` 的内容设计同样对标计划中的第 `6` 章后 `10` 关：
- 颜色：固定 `6` 色
- 形状：开放到前五章的全部正式形状
- 特殊机制：只使用 `方向限定目标块`（也就是玩家口语里的“单向块”）
- 不引入第 `7~11` 章的锁门、单向门、开关门、变色格、冰面

这意味着：
- 无限模式 `v1` 本质上是“前五章异形互锁 + 第六章方向限定”混合后的长期量产模式
- 它先把最稳定、最适合程序生成的一层做深，而不是急着把所有机制都塞进去

## 3. 无限模式的产品定位

### 3.1 它是什么
无限模式用于提供：
- 主线之外的长期内容续航
- 稳定可解、稳定可读、稳定高压的连续解谜体验
- 金币获取与道具消耗的长期闭环

### 3.2 它不是什么
无限模式 `v1` 不是：
- 轻松放松档
- 教学档
- 无限叠加新机制的实验场
- 终章级近乎唯解的极限模式

### 3.3 它的目标体验
玩家打开无限模式后，应感受到：
- 从第一关起就进入正式思考状态
- 不需要重新学习新规则
- 盘面持续有压迫感，但不是乱
- 关与关之间变化明显，但始终属于同一种“读盘语言”

一句话定义：
`一个长期维持在“第 6 章 brutal 成品带”附近的连续高质量动脑题流。`

---

## 4. 规则与内容边界

### 4.1 固定棋盘规格
无限模式 `v1` 固定采用手机优先规格：
- `cols = 6`
- 常用盘面：`6x9 ~ 6x10`
- `6x11` 不进入 `v1` 正式池
- `6x12` 明确不进入 `v1`

原因：
- 无限模式强调连续游玩，手机端稳定阅读比单关极限信息量更重要
- 一旦行数上去，生成器可以更容易塞信息，但玩家读盘和操作负担会明显增加

### 4.2 颜色与形状白名单
固定使用：
- 颜色：`red / blue / green / yellow / purple / orange`
- 形状：`mono`、`domino`、`bar3`、`square-2`、`L-3`、`L-4`、`T-4`、`cross-5`

说明：
- `L / T / 十字型` 不再按“轻松档禁用、动脑档开放”的方式拆档
- 它们是无限模式 `v1` 的正式语言之一
- 但生成时仍需用权重控制，避免整盘全是异形而发糊

### 4.3 机制白名单
无限模式 `v1` 允许：
- 普通目标块
- 多格目标块
- 异形目标块
- `方向限定目标块`
- `同色可多门` 的出口系统
- 锁门 / 钥匙格
- 单向门
- 开关门
- 变色格
- 冰面

但启用方式要收敛：
- `方向限定` 作为基础常驻层，用于保证读盘压力
- 第 `7~11` 章机制按回合阈值渐进解锁
- 单局默认只注入 `1~2` 个章节机制，不做高并发叠加
- 变色格优先 `1x1` 单格；冰面优先短条；开关门优先 `1~2` 格门体

无限模式 `v1` 仍明确不允许：
- 固定墙
- 独立阻挡块
- `Z/S`
- 可旋转块

### 4.4 为什么从第 6 章起步并渐进扩到第 11 章
当前无限模式不再停留在“只做第 6 章”，而是采用：
- 以第 `6` 章 `brutal` 带作为基础盘面密度和形状压力
- 再把第 `7~11` 章机制逐步接入
- 仍优先保证手机端可读、生成速度和长期重复度

因此 `v1` 的策略是：
- 先保证高密度几何互锁始终成立
- 再把锁门 / 单向 / 开关 / 变色 / 冰面作为低配额增强层
- 遇到坏题时允许通过金币道具兜底，而不是要求无限模式每局都保持主线级严校验

## 5. 无限模式单档参数

### 5.1 外显难度名与内部 tier
- 玩家看到的模式名：`动脑`
- 生成器内部可继续沿用技术名：`endless-peak`

但 `endless-peak` 的定义需更新为：
- 起步对标主线第 `6` 章后 `10` 关
- 中后轮次按阈值渐进混入第 `7~11` 章机制
- 不再对应旧三档系统里的“最高档”概念

### 5.2 建议参数带
建议 `v1` 正式量产参数冻结为：
- 常用盘面：`6x9 ~ 6x10`
- 目标占格率：`76% ~ 80%`
- 最少空格：`8 ~ 10`
- 目标块数量：`18 ~ 24`
- 门组数：`8 ~ 10`
- 门槽数：`11 ~ 14`
- 解法家族上限：`<= 2`
- 首步合法动作目标：`1 ~ 2`
- `difficultyScore` 目标带：`86 ~ 92`

说明：
- 这里不是要求每关都一样难，而是要求绝大多数候选关都落在这个稳定区间
- 当生成器有轻微波动时，可接受少量关卡落到 `84 ~ 94`
- 但不应出现明显接近主线第 `1~3` 章的低压盘

### 5.3 机制负载
方向限定块数量建议：
- 常态 `2 ~ 4`
- 高压样本 `4 ~ 6`
- 禁止把整盘都做成方向限定，否则会把谜题感扭成规则束缚感

### 5.4 异形比例
复杂异形（`L / T / 十字`）建议：
- 不低于总块数的 `30%`
- 常态控制在 `35% ~ 45%`
- 极端候选不高于 `50%`

原因：
- 太低则读盘过平，不像对标第 `6` 章后段
- 太高则手机上易发糊，且生成器更容易产出视感混乱的盘

## 6. 结构模板建议
无限模式 `v1` 的基础模板仍以高密度几何互锁为主，但允许低配额混入章节机关模板：
- `dense-interlock`：高密度互锁基础盘
- `dual-bottleneck`：双瓶颈串联
- `gate-competition`：门前共享整理区竞争
- `shape-weave`：异形编织与缺角借位
- `axis-commit`：方向限定块迫使承诺某条轴线
- `hidden-first-clear`：首步不露但题眼清晰
- `lock-detour`：锁门迫使先绕后开
- `one-way-fork`：单向门把整理顺序切成单边流
- `switch-pocket`：用压力开关维持短时通道
- `recolor-restore`：先踩染色格，再回到正确门系
- `ice-lane`：短冰道改变终点格

模板约束：
- 单局只抽取少量机关模板
- 机关模板不能压过几何互锁本身
- 手机端优先，所有机关都要保持图标和颜色可读

## 7. 生成流程建议
无限模式 `v1` 推荐流程如下：
1. 固定使用 `动脑` 档合同，不再做档位分叉
2. 选择 `motif` 与 `dependencyGraph skeleton`
3. 先构造近解态，确保每个关键块存在兼容门
4. 按第 `6` 章 brutal 目标带分配：颜色面积、形状面积、方向限定块数量
5. 执行 `逆向构造 + 补压`
6. 先跑 `staticValidateLevel()` 做静态过滤
7. 再跑 `quickValidateLevel()` 做低预算快验
8. 最后只对少量候选跑 `fullValidateLevel()`
9. 做 `signature` 去重与最近关打散
10. 通过后写入当前轮次候选缓存

## 8. 存档与局流

### 8.1 运行形态
无限模式不是单张永不结束的大地图，而是：
- 连续关卡流
- 每关独立开始 / 独立结算
- 通关后自动衔接下一关

### 8.2 保存字段
保存当前无限轮次时，只需记录：
- `mode = endless`
- `seed`
- `round`
- `streak`
- `earnedCoins`
- `currentLevelSnapshot`
- `candidateQueue`（若存在预生成缓存）

因为只有一个档位，所以：
- 不再需要保存 `difficultyId = relax / normal / think`
- 外显无限模式入口始终直接指向当前 `动脑` 轮次

### 8.3 继续与重开
玩家再次进入无限模式时：
- 若有未完成轮次，默认显示 `继续这轮`
- 次按钮为 `重新开始`
- 不再出现档位切换选择

---

## 9. 奖励建议
无限模式 `v1` 建议奖励：
- 每关完成：`80 金币`
- 连续完成 `5` 关：额外 `250 金币`
- 连续完成 `10` 关：额外 `600 金币`

设计理由：
- 只保留一个动脑档后，不需要再按档位拆奖励
- 该强度已经明显高于主线前几章重玩，奖励应足够大方
- 但也不应高到完全替代主线首次通关奖励

---

## 10. UI / UX 要求

### 10.1 首页入口
首页只显示：
- `∞ 无限模式`

不再显示：
- `轻松`
- `普通`
- `动脑` 三选一

### 10.2 无限列表
无限模式列表改为：
- 单一卡片 / 单一区域
- 只展示当前轮次信息
- 核心信息：
  - 当前连过数
  - 当前轮次
  - 本轮累计金币
  - 历史最佳

### 10.3 结果流
结果流保持两层：
- 单关完成小结算：不打断连续游玩
- 主动退出时总结弹窗：展示本轮成绩并提供 `继续这轮 / 重新开始 / 返回列表`

---

## 11. 与主线和生成器 v3 的关系

### 11.1 与主线的关系
无限模式 `v1` 不是主线的替代品，而是：
- 使用主线前六章已经验证过的稳定语言
- 不承担教学责任
- 不追求“每关都有鲜明的新东西”
- 追求“稳定密度 + 稳定烧脑 + 长时间可玩”

### 11.2 与生成器 `v3` 的关系
无限模式 `v1` 是 `v3` 的天然落地场景，因为它：
- 不需要章节教学包装
- 只保留一个档位
- 机制白名单更窄
- 非常适合 `章节合同 -> 结构模板 -> 依赖图 -> 静态快验 -> quick/full` 这条产线

因此后续生成器 `v3` 的优先顺序建议是：
1. 先把主线第 `2~5` 章与第 `6` 章的结构合同做稳
2. 然后直接把无限模式 `v1` 接成“第 `6` 章 brutal 基线的连续量产模式”

### 11.3 对生成器 `v3` 的直接合同
为了让无限模式可以尽快接到 `v3`，这里把它冻结为一个明确的生成合同：

- `profileId = endless-brain-v1`
- `visibleMode = 动脑`
- `tier = endless-peak`
- `cols = 6`
- `rows = 9 | 10`
- `colorCount = 6`
- `shapeWhitelist = mono / domino / bar3 / square-2 / L-3 / L-4 / T-4 / cross-5`
- `mechanicWhitelist = direction-limited-block`
- `occupancyRatio = 76% ~ 80%`
- `blockCount = 18 ~ 24`
- `doorGroupCount = 8 ~ 10`
- `doorSlotCount = 11 ~ 14`
- `openingActionCountTarget = 1 ~ 2`
- `solutionFamilyCountMax = 2`
- `difficultyScoreTarget = 86 ~ 92`

对应到 `v3` 的校验分层：
- `static`：只检查尺寸、颜色预算、形状白名单、门兼容、出口跨度兼容、占格率、重复签名、方向限定配置是否合法。
- `quick`：在有界搜索内估算 `difficultyScore / openingActionCount / firstClearSetupDepth / solutionFamilyCountEstimate`，快速过滤太空、太散、首步太明显的候选。
- `full`：只对少量候选做完整求解，确认 `isSolvable = true`、解法家族不超标、没有意外捷径、没有门判定漏洞。

对生成流程的硬要求：
- 先选 `模板家族`，再根据合同落 `颜色 / 门 / 异形 / 方向限定` 配额，不能随机乱摆后再碰运气筛题。
- 必须优先生成“首步不明显”的盘面，避免出现门口直接可出的显眼块作为开局提示。
- 同色允许多门，但门数量只为可解与制造竞争服务，不能为了复杂而堆无意义门槽。
- 候选池优先保留“高密度、低冗余、少解法家族”的局，而不是单纯步数长的局。

### 11.4 对运行时与存档的落地要求
无限模式运行时也要同步成单档模型，避免文档与代码再次分叉：

- UI 入口层不再出现 `轻松 / 普通 / 动脑` 三选一，只保留一个 `∞ 无限模式` 入口。
- 无限模式会话存档不再保存 `difficultyId = relax / normal / think`，统一改为：
  - `mode = endless`
  - `profileId = endless-brain-v1`
  - `tier = endless-peak`
- 当前局保存字段建议最少包括：
  - `seed`
  - `runIndex`
  - `clearedCount`
  - `coinsEarned`
  - `currentLevel`
  - `profileId`
  - `generatorVersion`
  - `startedAt`
- 老存档若存在 `relax / normal / think`，运行时统一迁移为 `endless-brain-v1`，不再保留旧档位选择。
- 导出备份时，无限模式只需要导出单一轮次状态与历史最佳，不再维护三档并存的数据结构。

---

## 12. 一句话结论
无限模式 `v1` 从现在开始冻结为：

`只保留一个“动脑”档，整体对标计划中的主线第 6 章后 10 关，内容边界固定为“前五章异形 + 第六章方向限定”，不再做轻松 / 普通双低档，也不急着引入第 7~11 章机关。`
