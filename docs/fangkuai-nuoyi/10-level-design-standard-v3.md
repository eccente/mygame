# 方块挪一挪关卡设计标准 v3.0

## 1. 文档定位
本文件用于把近期参考关卡图带来的结论，整理成后续可以直接驱动 `生成器 / 校验器 / 手工做关 / UI读盘` 的统一标准。

它重点回答四件事：
- 成品关卡的难点到底来自哪里
- 我们的棋盘、方块、出口应该如何协同设计
- 如何在“保证有解”的同时，做出足够强的结构、挑战性和趣味性
- 生成器和校验器后续需要补哪些硬约束与评分项

与其他文档的关系：
- `01-prd.md` 负责产品目标与范围
- `02-core-rules.md` 负责逻辑规则
- `03-level-and-endless.md` 负责主线与无限模式内容结构
- `09-mainline-specials-and-generator-spec.md` 负责生成器 / 校验器规格
- 本文件负责把“关卡应该长什么样、为什么这样设计”彻底说清楚

若后续出现“规则没错，但生成出来不好玩”的情况，优先回看本文件。

## 2. 参考关卡提炼出的核心结论
结合近期参考图，可以确认成品级关卡的难度并不主要来自步数、时间或大量机关，而是来自以下五类结构力量：

### 2.1 高密度互锁
- 盘面很满，但不是平均铺满，而是存在 `主瓶颈区 + 次瓶颈区 + 少量缓冲区`
- 玩家看到的是很多块，但真正能推进局面的动作很少
- 空位本身是稀缺资源，谁先借位、借给谁，比“谁能动”更重要

### 2.2 大块 / 异形块作为结构骨架
- `bar3 / square-2 / L / T` 不只是视觉变化，而是天然的空间骨架
- 大块负责分区、堵路、占位、延迟释放
- 小块负责做插销、桥接、门前守卫和临时腾挪点

### 2.3 出口参与解谜，而不是只做终点
- 成品关卡里的门不是“一色一个收纳口”这么简单
- 同色多门很常见，但它们并不是单纯降难，而是用来制造路线选择、门前竞争和顺序分流
- 真正高质量的门，会直接决定某个颜色到底该从哪一侧收束出局

### 2.4 局部战区
- 好关卡经常会把盘面自然切成 `2~3` 个局部战区
- 玩家先解决一个小局部，再借此打开另一个局部，而不是一上来全盘都能乱动
- 即使我们不使用固定墙，也可以靠大块摆位、门位分布、颜色冲突完成分区

### 2.5 少量正确路径
- 不是唯一解死题，但也不能是“怎么拖都能过”
- 开局通常会给玩家 `3~6` 个看似可行的动作
- 真正能导向通关的推进线通常只有 `1~2` 条
- 中盘可出现少量分支回流，终盘再重新收束

## 3. 我们的目标体验
本项目不是做竞速，也不是做高惩罚推箱式谜题，而是做：
- `看得懂`：手机上几秒内能读懂颜色、门和主要瓶颈
- `拖得顺`：连续滑动 + 吸附自然，不卡判定
- `想得出`：玩家能意识到题眼和局部顺序，而不是纯试错
- `解得爽`：每解开一层互锁，盘面明显松动，产生连续释放感
- `能一直玩`：无限模式和主线后段都能在高密度下保持新鲜度

这意味着我们后续所有关卡都应满足：
- 没有步数限制、没有时间惩罚，也依然能成立
- 每关都存在 `不用道具` 的正式解
- 道具只是缓冲，不进入关卡设计前提
- 难度来自结构，不来自信息噪音

## 4. 棋盘结构标准

### 4.1 基础盘面
- 固定 `6 列`
- 行数在 `8~12` 之间变化
- 主线常用 `6x8~6x10`
- `6x11` 用于高压关
- `6x12` 只在少数高压 / 无限高档位使用，且必须通过 `mobileViewportFit`

### 4.2 占地率
建议继续使用当前冻结结论：
- 教学关：`65%~70%`
- 常规关：`68%~76%`
- 高压关：`74%~80%`

注意：
- 占地率高不等于平均塞满
- 好盘面必须保留少量“值钱的空腔”作为借位区
- 这些空腔最好贴近主瓶颈或门前，而不是随机散落

### 4.3 局部结构角色
每一关至少应该能识别出以下几个空间角色中的 `2~4` 个：
- `主工作区`：玩家最先反复操作的区域
- `主瓶颈`：必须解开的核心堵点
- `副瓶颈`：主瓶颈解开后才显现价值的第二层卡点
- `缓冲腔`：用于临时借位和错车的小空区
- `门前区`：出口附近的最后整理区

### 4.4 反例
以下盘面不应进入正式关卡池：
- 大片均匀空旷区域，移动几乎不需要腾挪
- 关键信息全部挤在顶边 / 底边角落，手机上读不清
- 盘面虽然很满，但没有明显题眼，只能盲试
- 各区域之间几乎不发生竞争，像分开做几个独立小题

## 5. 门系统设计标准

### 5.1 定位
门不是结算装饰，而是正式的关卡结构参数。

门需要同时承担四个职责：
- `颜色终点`
- `路线控制器`
- `顺序调节器`
- `局部瓶颈的收束口`

### 5.2 术语
为了后续生成器、校验器和美术实现统一，定义以下术语：
- `门组`：同一边上连续的一段同色出口
- `门槽`：门组覆盖的单个边界格
- `主门`：设计者预期主解更常使用的门
- `辅门`：同色第二出口，用于可解性补偿或路线分流
- `竞争门`：多个块会抢其前方借位空间的门

### 5.3 门宽标准
在当前正式形状池 `mono / domino / bar3 / square-2 / L-3 / L-4 / T-4 / cross-5` 下，门宽统一采用：
- `span = 1`
- `span = 2`
- `span = 3`

当前不建议生成 `span = 4`：
- 现有正式形状的单侧投影最大值为 `3`
- 更大的门会明显放松门前压力
- 手机上也更容易把边界染色做得过重

### 5.4 多门原则
- 每种活跃颜色至少存在 `1` 个门组
- 同色允许存在 `多个门组`
- 同色多门的目的只能是以下三种之一：
  - `保证可解`
  - `制造路线分支`
  - `制造门前竞争`
- 不能为了“看起来丰富”而乱加门

### 5.5 门数量建议
按难度带控制两个指标：`门组数` 与 `门槽数`

| 难度带 | 门组数 | 门槽数 | 说明 |
| --- | --- | --- | --- |
| `teaching` | `5~7` | `7~9` | 清楚、直观，但不能退化成一色一门的空盘 |
| `regular` | `6~8` | `8~11` | 开始形成同色双门与边侧分流 |
| `high-pressure` | `7~10` | `10~13` | 多色多门共存，但必须保留题眼 |
| `endless-peak` | `8~10` | `11~14` | 允许更复杂的门预算，但不能稀释结构 |

### 5.6 摆放原则
门位不能平均撒点，应遵循以下规则：
- 至少启用 `2` 条边，常规高质量关建议启用 `3` 条边
- 主门优先放在 `主瓶颈自然延伸` 的边上，而不是按颜色平均分布
- 同色重复门优先分散到不同边，避免同边堆叠变成纯放水
- 门前应存在 `1` 层以上结构压力，不能一开局就是大空地直通
- 角位附近门只能少量使用，且更适合作为辅门，不适合作为整关主门
- 同一边相邻门组之间必须保留深色围栏分隔，避免视觉连成一整条彩条

### 5.7 门与关卡难度的关系
- `低难`：门位直观，重复门少，门前阻挡弱
- `中难`：开始出现同色双门、门前竞争和路线选择
- `高难`：门不一定少，但不同门之间会共享通道 / 共享借位空腔，顺序依赖更强

### 5.8 离场判定标准
正式离场判定继续冻结为：
- 当前移动方向必须正对门所在边
- 方块必须贴边
- 方块颜色必须匹配
- 方块在该边上的 `完整投影跨度` 必须被门组完全覆盖
- 方块必须在后续结算中 `整体越过边界` 才算清除

这条规则的关键意义在于：
- 门宽真正参与设计
- 大块与异型块不会“蹭到一点门就消失”
- 门与方块形状形成明确联动

### 5.9 门前竞争标准
高质量关卡建议至少满足以下一项：
- 至少 `1` 个门前区由两个不同颜色共享借位空间
- 至少 `1` 个门前区由异型块制造卡口
- 至少 `1` 个颜色存在“看似最近的门不是最佳门”的分流判断

## 6. 方块角色设计标准
虽然所有方块都是目标块，但在关卡设计上应为它们分配不同功能角色：

### 6.1 推荐角色
- `主锚块`：面积大、站中路、决定主节奏
- `守门块`：位于门前区，负责制造最后一段整理压力
- `插销块`：面积小，但卡在关键借位点
- `桥接块`：连接两个局部战区，移走后两个区域开始联动
- `连锁释放块`：一旦移走，能同时释放 `2~3` 个后续动作
- `竞争块`：与其他颜色共享通道或共享空位，制造顺序冲突

### 6.2 形状定位
- `mono`：补空、做插销、做局部节奏控制，不宜过多
- `domino / bar3`：构成基础车道与横竖冲突
- `square-2`：制造强占位和大面积门前清障需求
- `L-3 / L-4`：制造缺角借位、边界错位和门前转折
- `T-4`：制造中心堵点、桥接卡口和双侧分流压力
- `cross-5`：制造十字锚点、中轴锁喉与四向共享借位

### 6.3 面积与体积的一致性
后续所有形状建模、逻辑占格、门宽判断、拖动碰撞都必须遵循同一构建逻辑：
1. 先确定 `shapeCells`
2. 再确定外轮廓底面
3. 再从底面统一拔高成 3D 模型
4. 最终碰撞、吸附、离场、阴影、高光都只认同一套 footprint

这样可以从根源避免“异型块看起来比占格更小 / 更大”的问题。

## 7. 难度来源与章节节奏标准

### 7.1 难度优先级
后续正式关卡的难度来源优先级应该固定为：
1. `首出时机与首出收益`
2. `顺序依赖`
3. `空间竞争`
4. `门前冲突`
5. `颜色搜索宽度`
6. `机制附加约束`

这里的 `首出时机与首出收益`，指的是：
- 第一个离场方块要不要先准备多步
- 第一个离场方块是不是关键大块 / 关键结构块
- 首出后释放的是局部空间，还是直接把整盘做穿

主线关卡应优先避免：
- 开局直接白给出门
- 首出虽然晚，但只是一个低收益小块
- 首出之后整盘瞬间失去约束

不建议把难度主要建立在：
- 纯操作精度
- 隐藏规则
- 过度对称导致的纯枚举试错
- 过多新机制同时混入

### 7.2 章节颜色节奏
- 第 `1` 章：固定 `4` 色
- 第 `2` 章：固定 `5` 色
- 第 `3` 章起：固定 `6` 色全部上

颜色增加的意义不是“更花”，而是增加玩家同时要跟踪的路线数量。
因此颜色增加时，必须同步提高：
- 占地率
- 形状复杂度
- 门位竞争度

### 7.3 新机制教学原则
- 新机制第一次出现时，只做 `1` 关教学关
- 教学关也必须是正式密度，不做幼儿园大空盘
- 教学目标是在 `20~40 秒` 内让玩家自然完成一次关键机制触发
- 第二次出现开始，就必须和既有颜色 / 形状 / 门位结构混编

## 8. 生成器硬约束（v3 建议）
以下约束不满足时，候选关直接废弃：
- `cols = 6`
- `rows ∈ [8, 12]`
- 当前正式生成内容默认 `不使用固定墙`
- 第 `1/2/3+` 章颜色数必须分别为 `4 / 5 / 6`
- 占地率必须落在目标带内
- 每种活跃颜色至少存在 `1` 个兼容门组
- 当前正式形状池下，所有门组 `span ∈ [1, 3]`
- 每个方块在参考解中都必须存在至少 `1` 个完整兼容门组
- 不能出现“开局即可无脑连出多个颜色”的直通盘
- 不能出现“大块开局贴门、几乎不用借位就能首出”的结构
- 初始有效动作数必须落在目标带内
- 首出准备深度、首出面积、首出释放值必须落在章节目标带内
- 候选关必须在 `不使用道具` 的条件下被校验器解出
- 必须通过 `mobileViewportFit`

## 9. 校验器新增评分项（v3 建议）
除可解性外，校验器建议再补以下字段：
- `occupancyRate`
- `activeColors`
- `doorGroupCount`
- `doorSlotCount`
- `doorCompetitionCount`
- `openingActionCount`
- `firstClearSetupDepth`
- `firstClearArea`
- `firstClearReleaseGain`
- `firstClearRouteCount`
- `falseFirstClearCount`
- `solutionFamilyCount`
- `criticalPathDepth`
- `mainBottleneckScore`
- `mobileViewportFit`
- `unusedExtraExits`
- `unmatchedBlocks`

建议含义如下：
- `doorCompetitionCount`：统计门前共享借位 / 共享通道的关键冲突数
- `criticalPathDepth`：关键依赖链长度，越高表示越需要顺序思考
- `mainBottleneckScore`：评估是否存在清晰主瓶颈，而不是均匀松散

### 9.1 建议验收门槛
- `teaching`：`openingActionCount = 3~6`，`firstClearSetupDepth = 1~3`，`solutionFamilyCount <= 4`
- `regular`：`openingActionCount = 2~4`，`firstClearSetupDepth = 2~4`，`solutionFamilyCount <= 3`
- `high-pressure / endless-peak`：`openingActionCount = 1~3`，`firstClearSetupDepth = 3~6`，`firstClearRouteCount <= 2`，`solutionFamilyCount <= 2`

如果某关出现以下情况，应判定为质量不足：
- 首步几乎所有块都能有效推进
- 多个门只是在装饰性增加选择
- 整个过程没有明显“先解哪一层锁”的节奏
- 颜色虽多，但每色只是零星点缀，不构成真实搜索压力

## 10. 手工做关与生成器共用模板
为了降低后续章节开发和调参成本，建议后续所有关卡都尽量归入以下模板思路：
- `dense-interlock`：高密度基础互锁型
- `dual-bottleneck`：双瓶颈串联型
- `gate-competition`：门前竞争型
- `shape-weave`：异形编织型
- `staged-release`：分阶段松动型
- `mechanic-anchor`：新机制挂在单一主瓶颈上的教学型

每个模板都应描述：
- 主工作区位置
- 主瓶颈位置
- 副瓶颈位置
- 活跃边数
- 门组预算
- 形状预算
- 颜色预算
- 关键事件链示例

## 11. 当前冻结结论
基于以上分析，当前阶段建议正式冻结以下结论：
- `固定 6 列` 不变
- 主线与无限模式正式内容默认 `无固定墙`
- 所有可移动块都是目标块
- 门系统采用 `同色可多门 + 门宽 1~3 + 完整跨度离场`
- 关卡强度主要靠 `高密度互锁 + 门前竞争 + 少量正确路径`
- 新机制只给 `1` 关教学，随后立即进入正式强度
- 生成器与校验器下一阶段都必须正式把 `门组 / 门槽 / 门前竞争` 纳入质量控制

## 12. 下一步落地建议
后续建议按以下顺序推进：
1. 先把本文件中的 `门系统标准 / 关卡结构标准 / 校验项` 回写到相关规格文档
2. 再补生成器与校验器的数据字段和验证项
3. 然后重做第 `1~5` 章样本关
4. 样本关通过后，再批量扩章与接入无限模式
