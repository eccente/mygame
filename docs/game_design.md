# 车辆离场解谜 Web 版完整设计方案（Python）v2.0

## 1. 文档目标与范围
本方案用于定义新版核心玩法，并作为后续开发与测试的唯一基线。

本版相对旧版的关键变化：
- 不再是“主车出门”玩法。
- 改为“大地图 + 点击自动行驶 + 全车离场”。
- 难度核心从“局部堵塞”转为“由外到内的剥离顺序 + 步数预算控制”。

范围包含：
- 核心玩法与规则
- 教学关与无限关设计
- 可解关卡生成方案
- 美术、交互、技术架构
- 开发里程碑与验收标准

不包含（后续迭代）：
- 联网对战
- 账号与云存档
- 付费系统

## 2. 产品定位
- 类型：轻度益智、单机、回合制、低压无时限
- 平台：手机浏览器优先（Web），桌面浏览器兼容
- 单局体验：2-6 分钟
- 核心卖点：
  - 单手点击操作，零精细操作要求
  - 车辆自动行驶，规则直观
  - 目标清晰：清空场内所有车辆
  - 关卡可无限生成且保证可解

## 3. 核心玩法定义（新版）

### 3.1 游戏目标
清空棋盘上的所有车辆即通关。

### 3.2 棋盘规格
- 关卡 1 起始棋盘：`5 x 6`
- 随关卡推进逐步扩展，最终达到：`10 x 20`（竖屏优先）
- 尺寸增长方式：按关卡编号线性插值并取整（宽高均单调上升）
- 边界定义：棋盘最外圈为离场边界

### 3.3 车辆定义
首版（MVP）规则：
- 每辆车有固定停放轴向
- 轴向：水平/垂直
- 车辆长度：仅 `1` 或 `2`
- 长度分布：随机生成时 `1` 占 `60%`，`2` 占 `40%`
- 车辆不可旋转

### 3.4 拖拽选向后自动行驶规则
玩家按住车辆并沿车辆轴向拖拽来决定方向：
- 水平车：可选 `LEFT` 或 `RIGHT`
- 垂直车：可选 `UP` 或 `DOWN`

松手后，车辆会沿所选方向自动持续行驶，直到触发以下两类结果之一：

1. `碰车停止`
- 前方路径遇到其他车辆，停在碰撞前最后一个合法位置。

2. `触边离场 / 围栏阻挡`
- 若边界该位置无围栏：车辆离场（从棋盘移除）。
- 若边界该位置有围栏：车辆被围栏挡住并停止。

### 3.5 新增障碍规则
- 棋盘最外圈会随机分布围栏（Fence）。
- 行人（Pedestrian）在限定巡逻区来回移动。
- 汽车在移动过程中若与行人发生碰撞，立即判定失败。

补充规则：
- 若车辆前方第一步即被阻挡，则本次点击不产生位移。
- 每次“有效移动点击”（车辆发生位移或离场）计为 1 步。
- “无效点击”（车辆完全不动）默认不计步（可配置项）。

### 3.6 胜负与步数
- 胜利：场内车辆数为 0
- 失败：`moves_used > max_steps` 或“撞到行人”
- 失败后允许：重开、撤销（若开启）、继续观察布局

### 3.7 评分机制
- 3 星：`moves_used <= optimal_moves + 0`
- 2 星：`<= optimal_moves + 3`
- 1 星：`<= max_steps`
- 0 星：超出 `max_steps`（失败）

## 4. 关卡结构与模式

### 4.1 教学模式（固定关）
目标：让玩家快速建立“由外到内剥离”的解题心智。

建议首版固定 40 关：
- 1-10 关：理解轴向拖拽与自动行驶
- 11-20 关：理解“阻挡后停靠再二次移动”
- 21-30 关：引入多层阻挡与顺序依赖
- 31-40 关：紧凑步数预算

### 4.2 无限模式（程序生成）
- 按难度层持续生成
- 每关携带 seed，便于复现与调试
- 保证可解并符合步数区间

## 5. 难度模型

### 5.1 难度维度
- `car_count`：车辆总数
- `board_density`：占用密度
- `dependency_depth`：需要先清除的阻挡层级
- `optimal_moves`：最优步数
- `efficiency_margin`：`max_steps - optimal_moves`

密度约束（首版硬规则）：
- 车辆占地面积 / 棋盘总面积目标区间：`60% - 70%`

### 5.2 首版难度分层
- Easy：车辆 12-16，最优步数 10-18，步数余量 6-8
- Normal：车辆 16-22，最优步数 19-30，步数余量 5-7
- Hard：车辆 22-28，最优步数 31-45，步数余量 4-6
- Expert：车辆 26-34，最优步数 46+，步数余量 3-5

## 6. 可解关卡生成（核心）

### 6.1 生成原则
使用“逆向构造 + 求解校验”的组合流程：
- 先从终局（空棋盘）反向构造初始局面
- 再用求解器验证该局面确实可清空
- 最后按难度指标筛选

### 6.2 逆向构造流程
1. 终局初始化
- 棋盘为空。

2. 逆向加入车辆
- 每次加入一辆车并指定轴向。
- 每辆车长度仅在 `1/2` 中采样，概率固定为 `60% / 40%`。
- 车辆放置位置通过“反向滑入”得到，使其在正向中具备移动轨迹。
- 控制部分车辆形成多层阻挡关系，提升 `dependency_depth`。

3. 状态合法性检查
- 不重叠、不越界、轴向合法。

4. 去重与多样性
- 用状态哈希去重。
- 控制车辆轴向比例和密度波动，降低重复感。

### 6.3 求解器校验
使用最短路搜索（BFS/A*）在“点击动作空间”求解：
- 状态：所有在场车辆的位置与在场标记
- 动作：点击任意在场车辆一次
- 转移：按自动行驶规则得到唯一后继状态
- 目标：在场车辆数为 0

输出：
- `is_solvable`
- `optimal_moves`
- 一条最优动作序列（用于提示）

不满足条件则丢弃重生。

### 6.4 步数预算生成
- `max_steps = optimal_moves + margin`
- `margin` 按难度分层配置
- 教学关可使用更宽松 margin

## 7. 规则细节与边界约定
- 同一点击仅驱动一辆车
- 车辆不会推动其他车辆
- 车辆不会转向
- 车辆离场后不再回场
- 若点击时已通关或已失败，不再响应车辆移动

## 8. 数据结构（Python）

### 8.1 Vehicle
- `id: str`
- `x: int`, `y: int`（锚点）
- `length: int`（仅 1 或 2，随机生成时 60%/40%）
- `axis: str`（`H`/`V`）
- `style_key: str`
- `active: bool`（是否仍在场）

### 8.2 LevelData
- `level_id: str`
- `seed: int`
- `board_w: int`, `board_h: int`
- `vehicles: list[Vehicle]`
- `fences: list[Fence]`（边界围栏）
- `pedestrians: list[Pedestrian]`（巡逻行人）
- `optimal_moves: int`
- `max_steps: int`
- `difficulty: str`

### 8.3 RunStats
- `moves_used: int`
- `undo_used: int`
- `hint_used: int`
- `elapsed_sec: float`
- `result: str`（WIN/FAIL/QUIT）

## 9. 交互与 UI 规范（移动端）

### 9.1 输入规则
- 按住车辆并沿轴向拖拽选方向，松手后自动行驶
- 非轴向拖拽不触发移动
- 支持按钮：撤销、重开、提示

### 9.2 HUD 信息
- 顶部：关卡号、剩余车辆数、步数 `moves_used/max_steps`
- 底部：撤销、重开、提示、暂停
- 通关弹层：用步数、最优步数、星级
- 失败弹层：超步数提示 + 重开

### 9.3 动效反馈
- 有效移动：平滑直线滑动（200-350ms，按距离缩放）
- 阻挡不动：轻微抖动反馈（80-120ms）
- 离场：车辆缩放淡出或快速滑出
- 行人：在巡逻区做往返移动，随车辆移动过程同步更新

## 10. 美术风格规范
- 风格：明亮卡通、轻松治愈
- 地图表现：停车场或街区网格
- 车辆：色块清晰，强调轴向长度与位置关系
- 围栏：边界高对比阻挡线
- 行人：小体积高识别度图标，避免与车辆混淆
- 背景：浅暖色，不干扰阅读

建议配色：
- 背景：`#F7F4EA`
- 棋盘：`#E6D8B5`
- 网格：`#CCB98A`
- 文字：`#2D3A3A`
- 车辆主色组：`#4DA6FF` `#7ED957` `#FFC857` `#FF6B4A` `#B08CFF`

## 11. 音频策略
- 点击：轻短音
- 碰车停止：轻碰撞音
- 离场：清脆“通过”音
- 通关：短促正反馈音阶
- 默认可静音

## 15. 开发里程碑（新版）

### M4：打磨与 Web 发布（1 周）
交付：
- 完整 UI 与反馈动效
- 教学关 40+ 与无限模式

验收：
- 手机浏览器稳定可玩

## 16. 首版完成标准（DoD）
满足以下全部条件视为首版完成：
- 手机上网页可直接游玩
- 点击车辆可自动行驶
- 规则严格满足“碰车停、触边离场”
- 通关目标为清空所有车辆
- 有步数预算并可失败/重开
- 提供撤销、提示
- 有固定教学关与无限关
- 自动化核心测试通过
